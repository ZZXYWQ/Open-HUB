# COMPX 性能多行写入的条件恢复

开发分支修复，作用于现有10个精确COMPX连接项的性能设置，没有新增型号或固件兼容声明。

旧路径逐行调用会自行恢复的单行写入，外层失败后又写回所有尝试行；其他软件在失败期间改动性能行时，可能覆盖新状态。现在性能设置先保留地址10/169/181中实际涉及的完整原行，再重新核对所有原值，逐行写入并核对全体预期状态。未改变的行不发送SET。

共用宏事务已使用的不递归恢复行写入原语，由性能事务统一决定恢复。当前每个已尝试行只允许等于原值或本次完整目标值；未尝试行必须等于原值。未知部分值、第三方新值或邻接字段变化不被当作本次数据，不再盲目恢复。允许恢复时倒序逐行写回，紧前及写后核对全部相关行与单位/当前板载组；恢复失败立刻停止，不把尝试发送报告为恢复已确认。

保留原来的参数范围、逐字节标量校验、未知传感器模式和非选字段。其他品牌和Pulsar的独立路径未变。没有新增公开原始EEPROM接口、依赖、前端代码或资源。

## 验证

新增五项默认测试遍历全部有性能能力的精确型号：所有涉及写入阶段的动作前/后错误可回到精确原始EEPROM；40组所选/邻接/未尝试行的外部或部分修改保留且不写恢复；首个SET前原值变化零SET；写后切组只出现初次SET；恢复自身失败不重试、不报告确认。既有宏和性能原生测试保持通过。

X1 Lite实际构建UI的完整方案、十连接性能UI方案分别重新经过生产配置包导入、编译及原生事务执行。全量1015项通过、0失败、85项显式桥接默认忽略；两项受影响桥接单独通过，原生构建通过。无新增前端字节或运行依赖。

## 边界

全部为合成传输与模拟IPC，没有实机或固件原子事务证明。协议没有排他锁/原子比较写入，读取间改动又改回等竞争不能保证发现。原始行快照在内存中，不是新增的持久故障日志或厂商完整备份。此改动限于性能多行路径，不代表DPI、颜色等仍使用通用单行写入的路径已完成同样审计。
