# 罗技原生灯区开发范围

状态：开发分支已接入 HID++ 0x8070 的动态灯区发现、关闭/常亮/呼吸/光谱循环、回读校验与对应设置界面。属于实验性增量，没有达到完整型号验收，未生成或安装新的安装包。

## 已实现

设置页只在鼠标实际报告 0x8070 时显示“打开鼠标灯光”。打开后读取灯区位置、该区的效果槽、效果编号和当前的 11 字节状态；按设备返回内容显示。效果槽与效果 ID 分开处理，不能假设“编号 1”一定存在于每个灯区。未知原厂效果和参数保持原样，界面不把它们换成模板值。

当前可设置关闭与常亮 RGB、呼吸颜色/亮度及光谱循环亮度。呼吸与循环只在该灯区实际报告对应效果时开放；切换效果使用该效果报告的非零节奏值，修改现有效果则逐字节保留它的节奏。当前不把这些设备值统一解释为毫秒或开放速度输入；未报告可用节奏的未激活效果不会被填入猜测值。亮度为 1–100%，原生 0 编码表示 100%；关闭使用独立效果。现有呼吸波形和其他未知参数默认保留；新增明确选择的原厂默认、正弦、方波、三角、锯齿、鲨鱼鳍和指数波形。保留选项继续发送原有 Breathing 动作，只有明确选形才使用新增动作，其他原始参数和节奏保持。单色设备本轮只读。只有直接 USB、可读回当前状态及支持的协议版本允许写入；接收器暂只读，等待永久物理身份固定。每次只修改当前选定鼠标的一个灯区。输出末字节为 0，只写 RAM，不写闪存、不切板载/软件模式，也不修改 DPI、按键、宏、其他灯区或其他品牌。

预览同时记录当前鼠标的单位/连接身份；应用时拒绝另一连接的旧请求。已识别 HID++ 单位 ID 的设备，在写入前和写入/恢复后的归属检查中再次核对单位 ID，换鼠后不向新单位恢复原值。应用前重新发现能力并比较预览时的原始灯区状态，拒绝过期修改；应用后逐字节回读。若写入超时或回读失败，只在灯区仍是本次目标值、能力和板载模式/档位归属没有改变时恢复原值并回读。若灯区出现第三方新值、能力/档位改变或恢复不能核实，则报告状态不确定，不盲目覆盖，也不报告成功。

## 来源与验证

协议交叉来源为 [libratbag 固定提交](https://github.com/libratbag/libratbag/tree/8235b5bb6032dea15901ab58a8218956f4494d08) 的 0x8070 查询/设置、灯效记录事实，以及 [LogitechGDeviceInfo 的 MIT 灯效实现](https://github.com/infinitysky/LogitechGDeviceInfo/blob/e19565d9f14d23c7e7c8eb6b674c3de907243515/src/features/rgb.rs)。后者固定提交 `e19565d9f14d23c7e7c8eb6b674c3de907243515`，版权 2026 infinitySKYLi，许可随包保留为 Logitray-MIT.txt。没有捆绑其程序或运行依赖。

原有测试之外，新增呼吸/循环报文、亮度编码、设备节奏及未知参数保留、缺少节奏/非法亮度/单色拒写、丢失确认后的选定灯区恢复、连接身份和写入前后单位变化验证。两套灯光界面测试把关闭/常亮以及呼吸/循环的实际 IPC 参数回放到生产事务。包括效果 ID 与槽不相等、未知原状态、单灯区保留、短回复、丢失写入确认、拒绝、其他软件修改、档位/能力变化、恢复失败、两个同型号传输独立。测试中的 G502 HERO 是合成协议场景，不是该型号的实机兼容声明；本项目没有罗技实机。

当前应用默认测试 422 项及 14 项显式跨层测试通过。上一轮全量 27 套界面测试通过，本轮重新验证两套受影响灯光界面（新增一套，现有总数 28）。测试不操作物理罗技鼠标，不证明原厂视觉效果或全部型号兼容性。没有新增运行依赖。

后续传输改进将严格读取接到真实 HID++ 接收/请求路径：观察到的 0x10 报文要求 7 字节、0x11 要求 20 字节；错误长度不会补零为成功数据。板载描述符/扇区和原生灯效使用不补齐的 3/16 字节真实协议载荷，旧接口对合法短报文保留兼容补齐。另有生产消费者测试确保这些读取没有落回旧补齐接口。此保证针对 hidapi 实际交给应用的报文边界，不能证明操作系统未隐藏的更底层 USB 错误。

## 仍未完成

0x8071 的软件灯光所有权事务、波浪等其他原生效果、每个型号的速度单位和实际亮度行为、板载保存、配置中心持久化与原厂 G HUB 灯效导入、原生电脑光同步，以及逐型号实机和原厂 UI 品质验收。当前没有把部分灯区功能计作完整品牌或完整鼠标支持。


呼吸/循环的参数位置额外交叉核对 [Solaar 固定版本的协议定义](https://github.com/pwr-Solaar/Solaar/blob/e7304c4c451cc9bb4f206a914844525e67856a28/lib/logitech_receiver/hidpp20.py)。只使用互操作协议事实，没有复制该项目源码或新增其运行依赖。设备报告的节奏仅按原值传递，不据此宣称所有型号具有相同时间单位。

后续开发增量增加 [独立的预览连接校验](NATIVE-PREVIEW-CONNECTIONS.md)：稳定配置归属与当前连接标记分别核对；旧连接请求零 HID 拒绝，宏草稿可显式刷新保留。

呼吸波形后续增量依据已固定 Solaar 协议定义的 effect0x0A/form 参数位置与0–6枚举，不猜测0x8071软件所有权。七种明确波形、未知原波形保留、非法值零写入、超时和第三方/档位改变后的有条件恢复，以及八条实际界面请求的生产事务回放经过模拟。没有罗技实体视觉或时序验证，未增加完整型号数。[本轮验证](development/2026-10-26-shiftxy-waveform-validation.json)。

后续加入[现有扩展循环/波浪的饱和度与亮度编辑](LOGITECH-EXTENDED-LIGHTING.md)：仅对已激活且唯一枚举的0x15/0x16开放，方向、节奏、保留字段不变；没有开放基础波浪0x04或8071。生产事务、构建界面及请求回放验证通过。
