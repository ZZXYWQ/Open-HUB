# MCHOSE 身份读取与发送失败处理

开发分支增量；完整型号验收仍为 0/100，已发布和安装版本保持 0.3.7。本次没有生成安装包，也没有鼠标设置写入。

## 原厂代码证据与重试边界

对固定 SHA256 的本地原厂网页缓存做静态解压和文本检查，没有执行原厂代码。编码器的报告头、命令位置、参数与 XOR 校验规则和现有实现一致，因此没有猜测或更换设备路由。

原厂 BR 在 FF 响应后最多请求五次，内部间隔 30ms；外层 hgt 最多调用四组，因此上限是二十次请求、十六次内部等待。Open HUB 采用这个有限上限，仅重试明确的身份未就绪响应。正常且合法的零电量身份直接返回，不要求电量大于零。未知型号、错误 VID、截断、校验错误、超时及断连不重试，也不自动重放任何设置命令。已有精确捕获的无校验 FF 响应仍只是错误，不能借此绕过成功响应校验。

## 连接失效处理

底层 HID 输出必须返回完整报告长度。短写、超长计数及写入错误使本次连接失效，清除等待的响应并通知等待者；每次连接只发出一次 Gone 事件供管理器重新扫描。下一条命令不能复用失效连接，也不能把迟到响应当成另一次请求结果。这个处理不代表设备设置已回滚，失败写入没有自动重试。

## 测试与实机结果

针对性十项测试通过，其中新增六项覆盖重试次数与等待、最后一次成功、其他错误不重试、型号与零电量校验、发送失败隔离及重新扫描事件。全量默认测试 731 项通过、0 项失败、57 项忽略；非测试开发构建通过。前端和依赖没有变化。

实际只读诊断执行二十次 0900 空参数身份查询，仍以 FF 身份不可用退出，退出码 1。没有后续读取宏内容，也没有鼠标设置写入。这证明有限重试已在实机运行，但不能说明 FF 的原因，不能据此认定鼠标休眠或固件故障。实际记录只存命令计数与摘要，未把本地完整配置公开。
