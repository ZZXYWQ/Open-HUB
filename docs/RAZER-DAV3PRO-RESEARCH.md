# DeathAdder V3 Pro：捕获核对与型号修正

开发中的协议增量，不是已完成的鼠标接入，不增加完整兼容数；未发布或安装；开发分支开放已核对的 DPI、回报率、省电字段和八个输入的完整已知两层记录；支持保留普通左键的条件改绑和原厂 Hypershift 联动；宏和其他未知控制仍继续适配。只核对 `1532:00B6` 有线与 `1532:00B7` 原配接收器，不把两种连接当成两款鼠标，也不推断其他接收器或版本。

根据[官方说明书](https://dl.razerzone.com/master-guides/RazerSynapse3/DEATHADDERV3PRO-00000182-en.pdf)将这两个精确编号原先错误的 35000 DPI 上限改为 30000。此型号没有 RGB、没有倾斜滚轮，原厂列出五个可编程按钮和一组板载配置。指示灯显示电量/档位，不能包装成原生可自定义 RGB 灯区。原厂宏、配置转换与完整型号 UI 仍继续核对。

新增独立完整报文来源为 [OpenMouse 公开实机记录](https://github.com/OpenMouse-Project/mouse-protocol/tree/ba20ec3c5b4d6eca934f5771a4e88271b547df2a/captures/razer-deathadder-v3-pro)，其维护者在固件 2.1、Windows 11 上记录有线与原配 HyperSpeed 接收器的当前 DPI、回报率与省电操作。这里抽取二十四组完整往返：十二组当前 DPI（800 / 3200 / 1600）和标准回报率（125 / 500 / 1000），另十二组自动休眠（60 / 900 / 300 秒）与低电量模式（5 / 50 / 30 %），涵盖写入、应答、查询及值回复，完整 90 字节、校验与顺序都经检查；有序列号的交换没有分发。报文事实在 `gearwise-razer/src/testdata/deathadder-v3-pro-captured-roundtrips.tsv` 与 `deathadder-v3-pro-captured-power.tsv`，无新依赖、无参考 TypeScript 执行或代码复制。

这组真实记录还证明该型号当前 DPI 查询选择器是 1，旧通用查询使用 0。新增精确型号路径保留其他型号的原查询行为。原生 Link 用真实捕获逐字节验证发送与回复；两个编号使用现有严格应答检查，校验、长度、事务、类别、命令及大小不匹配时不重发持久写入。

官方支持五个档位，公开记录并未测试档位表命令。驱动仍先尝试原生表读取；只有固件明确回复“不支持”才转用已核对的当前 DPI 查询并将可编辑能力限制为一个当前值。随后单值写入走已捕获的 `04/05`，不能把多档方案静默压扁。损坏、空表或超时不会被当作“不支持”，其他旧型号不借用这条退路。此退路的拒绝场景是构造模拟，不是公开实机记录已经覆盖过的行为。

原配接收器的公开会话拒绝 2000 Hz，不能按“Pro”名称开放高频或套用单独 HyperPolling 接收器能力。省电现已接通独立设备休眠（1–15 分钟）与低电量阈值（5–100%，步进 5%）。使用生产 Link 对十二组公开原始报文逐字节回放；这些字段不借用 COMPX 的传感器休眠协议。官方接收器还支持同时配对键盘与鼠标，后续逐鼠标软件动作不能直接将整个接收器容器视为鼠标独有输入集合。

本项目没有此型号实物，公开捕获也没有覆盖它的按键写入、完整档位表、所有原厂功能或本项目 UI 品质。当前是上述功能的部分接入，不能作为新增完整适配发布。


省电事务先读取所有选中字段的原始值，再各写一次并逐项回读。百分比按原生 0–255 整数编码；当前原始值已对应所选百分比时不为舍入差异重写。不确定发送、忙状态或损坏回读不重发写入；失败后逐字段重新读取，只有当前值仍等于本次目标值才恢复精确原字节，第三方已改值保留，恢复失败也不自动重发。故障路径由构造内存传输验证，不能称为实物故障测试。

开发界面使用原生能力 DTO：显示对应原厂外观图、完整 XY 档位表或明确拒绝后的当前值、原配接收器支持的回报率和两个省电控制组。不显示此型号没有的 RGB、其他品牌消抖开关或尚未核实的宏编辑器。普通层按键只显示已完整读取到原动作的输入。当前值退路的 UI 明示只编辑当前 DPI，不能将原厂五档表覆盖成单档。两种连接的完整五档和当前值两种模式共四套方案，均经过浏览器编辑保存、实际配置存储重新载入以及生产驱动回放。模型图片为原厂页面的未修改 300×300 PNG，36,407 字节，来源与哈希在 `DEVICE-ARTWORK-SOURCES.json`。

本轮验证：538 项应用默认测试、36 项显式配置/界面交叉测试、322 项核心及驱动单元测试和 1 项文档测试通过；46 组完整后台界面回归通过。开发 EXE 只运行内存 HID 测试，不是安装包。本项目实机覆盖、完整动作/Hypershift/宏、原厂配置转换、校准与档位表实物时序等仍是缺口，新增完整验收数仍为 0。


后续静态研究直接下载并只读解包[官方 182 型号组件](https://cdn.razersynapse.com/1728899625Euq9w9FwRazer_182_0_Setup_v3.9.1130.101413.exe)，没有运行安装器或 DLL。`RzCtl_00B6.dll` 23.0.0.041210 的真实读取分派设置命令高位，五档查询与写入长度均为 38，记录为大端 XY/Z，写入记录编号从零开始；原厂 XML 核对了五档默认值和活动槽。另一份公开较新实现用 80 字节查询，此差异未直接用于物理设备。来源字节身份和函数位置见 [静态事实](development/razer-dav3pro-v3-static-facts.json)，只分发小型事实与原创实现，不分发原厂组件。

精确型号现使用严格完整表解析：配置组、长度、数量、活动槽、连续编号、XY 范围和未表示尾项分别核对；不再截断损坏活动索引。完整表写入和活动档切换均先读取最新表，写入一次再独立核对；失败只在仍保有本次目标值时恢复原表，第三方表保留，恢复失败不重发。旧单值方案碰到后来可读的多档表时拒绝应用，不能压成一档；完整表编辑保持 2–5 档，当前值退路继续只用已捕获的 `04/05`。

五档 GUI、30K XY 边界、活动档切换和 2–5 档增删以及四组界面保存方案均经过原生交叉回放。新增五项驱动回归覆盖原厂静态黄金向量、坏表、活动切换、新鲜外部值、忙状态、损坏回读、原值恢复失败和旧方案拒绝。这些仍为构造内存传输，不是本项目实机验收。

普通层按键后续增量直接对[官方 182 型号界面](https://apps.razer.com/synapse/products/182/ui/static/js/main.998a1822.js)做 AST 静态读取，核对左/右/中键、前进/后退、滚轮上下与底部 DPI 的八个固件编号；没有执行原厂脚本。原厂归档 DLL 的 `02/8C` / `02/0C` 为十字节记录：配置组、输入、层及七字节完整动作；静态分派核对实际调用沿用 `1F`，没有把另一分派参数误用为 `9F`。滚轮上下不提供原厂灵敏度功能，因此对应编辑器不开放 DPI 动作。

普通层现在接通七个非左键输入的原动作恢复、禁用、五键鼠标动作、完整左右修饰键快捷键、七种媒体动作，以及适用物理键的 DPI 升降、循环和 100–30000 狙击值。左键保持可用。未知原厂动作与不能无损表达的 XY 狙击值锁定，不被默认值覆盖。每次编辑先核对普通设备模式、读取完整当前记录，再单次写入并独立查询核对；失败只在当前仍等于本次目标时恢复精确原字节。第三方改值、未知层和恢复失败均不触发盲目重试。

新增五项原生驱动测试覆盖八个精确 ID、独立静态完整报文、256 种左右修饰位、七种媒体、DPI 动作、每个非左键输入、错误应答、忙状态、错误回读、外部改值、原值恢复失败和未知原厂绑定。四套实际 GUI 保存方案含七个独立动作，经配置文件保存/重载和生产编解码回放读回一致。开发 EXE 的 38 个传输项只做内存测试；它们不能计作 38 款完整兼容鼠标。没有新增运行时依赖，没有打包原厂 DLL 或分析工具。详细验证见 [本轮记录](development/2026-10-26-dav3pro-buttons-validation.json)。

Hypershift 后续增量使用独立原生层选择器：普通层为 0，第二层为 1，均核对相同八个物理编号。层信息由官方界面字典、默认 XML 与归档 DLL 的十字节记录交叉核对；按住切换的七字节动作另与 [razerqdhid 原作者协议记录](https://github.com/geezmolycos/razerqdhid/blob/4363a8836ab970c712fa8f2a9dd530a7e7bc5011/docs/cmd_button-en.md)比较，仅转录报文事实，没有复制或运行其程序。此参考基于 Basilisk，不能算作蝰蛇实机证据。本项目第二层和按住切换仍属于静态推导加模拟。

驱动本地控制编号明确区分普通层与第二层，任意高位整数不能截断成有效物理键。普通层保留左键，第二层允许独立编辑左键；右键、中键或侧键可设置原生按住 Hypershift。第二层不能套用切换动作，滚轮方向两层都不开放原厂列表没有的 DPI 选项。设备模式、配置组、物理输入和层在读取、写入、独立回读和失败恢复时分别核对，未知动作保持原始绑定。界面按层编辑，两个草稿切换后均保留；读不到第二层可用记录时关闭第二层编辑。

新增三项驱动回归遍历全部 u16 控制编号、独立完整静态向量、第二层八个输入、按住切换、两层互不覆盖及第二层故障恢复；另增加全型号模板隔离检查，其他品牌不接受此动作，也不将它编译成主机宏触发。四套 GUI 方案各含普通层七项和第二层八项，保存重载后生产驱动读回一致。539 项应用默认回归、36 项显式交叉、325 项驱动单元及 1 项文档测试、46 组后台 UI 回归通过，开发 EXE 仍仅运行 38 个内存传输项；本项目实物、完整原厂动作集、软件宏来源、Synapse 转换和校准继续开发。完整型号数仍为 0，安装版保持 0.3.7。见 [本轮验证](development/2026-10-26-dav3pro-hypershift-validation.json)。

左键保护后续回归覆盖原厂预先重映射的普通层：物理左键被改过时，其他输入可能成为唯一可直接使用的左键。因此替换这条原生动作前重新读取普通层其他输入，确认还有一个直接左键；Hypershift 层的左键不能代替此条件。失败恢复也使用同一检查，不为回到旧字节而删除本次刚恢复出的唯一左键。这两项生产传输测试及539+36项应用回归、327+1项驱动/文档回归通过；未改界面，未生成安装包。[验证记录](development/2026-10-26-dav3pro-left-click-guard-validation.json)。

校准继续使用同一官方组件做静态核对，当前已确认精确选择器 `[0,4]`、JSON 属性到低层命令的路由及按原字节传入的边界；26级 Pro 的主机转换仍未确认，暂不启用写入。还发现配置 JSON 读取只做零长度尺寸询问，不能当作硬件有效值。[校准研究事实](development/razer-dav3pro-calibration-static-facts.json)仅记录确定的字段、函数位置和缺口。


后续按键增量补齐物理左键的条件改绑：先把普通层左键功能分配到另一已知输入，再允许修改物理左键；完整普通层表没有直接左键时在任何写入前拒绝。生产编译先建立左键，再应用其余普通层和第二层。修改与恢复都重新核对目标及左键见证记录，第三方改值不覆盖。这不是设备级原子事务，外部软件仍应关闭。

官方同一182型号的惰性按键编辑组件证明，设置 Hypershift 会创建同一输入的普通层和第二层两条切层记录，离开切层时移除第二层覆盖，回到物理默认动作。驱动据此更新两条记录并分别回读；第二项失败只尝试一次有条件恢复，完整对最终再核对。未知第二层在进入前拒绝覆盖；退出时保留非本次切层动作。切层按键本身的第二层不能另行编辑，未知普通层也锁定对应第二层。七字节 Fn12 来自同协议其他型号事实，与精确B6记录传输组合而成，未获得本型号实机捕获，不能宣称实体按住/释放已验收。[官方组件事实](development/razer-dav3pro-hypershift-static-facts.json)。

新鲜设备读取会把所有完整已知按键记录一并保存进方案，而不是仅保存编辑过的项。界面键码选择过滤到驱动实际开放范围。仍有完整键码名称、原厂高级动作与宏等缺口，八个输入或十六条记录不代表完整动作集。
