# DeathAdder V3 Pro：捕获核对与型号修正

开发中的协议增量，不是已完成的鼠标接入，不增加完整兼容数；未发布或安装，尚未开放应用型号入口。只核对 `1532:00B6` 有线与 `1532:00B7` 原配接收器，不把两种连接当成两款鼠标，也不推断其他接收器或版本。

根据[官方说明书](https://dl.razerzone.com/master-guides/RazerSynapse3/DEATHADDERV3PRO-00000182-en.pdf)将这两个精确编号原先错误的 35000 DPI 上限改为 30000。此型号没有 RGB、没有倾斜滚轮，原厂列出五个可编程按钮和一组板载配置。指示灯显示电量/档位，不能包装成原生可自定义 RGB 灯区。按键、Hypershift、原厂宏、配置转换与完整型号 UI 仍继续核对。

新增独立完整报文来源为 [OpenMouse 公开实机记录](https://github.com/OpenMouse-Project/mouse-protocol/tree/ba20ec3c5b4d6eca934f5771a4e88271b547df2a/captures/razer-deathadder-v3-pro)，其维护者在固件 2.1、Windows 11 上记录有线与原配 HyperSpeed 接收器的当前 DPI、回报率与省电操作。这里仅抽取十二组当前 DPI（800 / 3200 / 1600）和标准回报率（125 / 500 / 1000）的写入、应答、查询及值回复，完整 90 字节、校验与顺序都经检查；有序列号的交换没有分发。报文事实在 `gearwise-razer/src/testdata/deathadder-v3-pro-captured-roundtrips.tsv`，无新依赖、无参考 TypeScript 执行或代码复制。

这组真实记录还证明该型号当前 DPI 查询选择器是 1，旧通用查询使用 0。新增精确型号路径保留其他型号的原查询行为。原生 Link 用真实捕获逐字节验证发送与回复；两个编号使用现有严格应答检查，校验、长度、事务、类别、命令及大小不匹配时不重发持久写入。

官方支持五个档位，公开记录并未测试档位表命令。驱动仍先尝试原生表读取；只有固件明确回复“不支持”才转用已核对的当前 DPI 查询并将可编辑能力限制为一个当前值。随后单值写入走已捕获的 `04/05`，不能把多档方案静默压扁。损坏、空表或超时不会被当作“不支持”，其他旧型号不借用这条退路。此退路的拒绝场景是构造模拟，不是公开实机记录已经覆盖过的行为。

原配接收器的公开会话拒绝 2000 Hz，不能按“Pro”名称开放高频或套用单独 HyperPolling 接收器能力。后续省电、休眠和低电量阈值仍须各自通过原始报文、完整状态及失败路径核对。官方接收器还支持同时配对键盘与鼠标，后续逐鼠标软件动作不能直接将整个接收器容器视为鼠标独有输入集合。

本项目没有此型号实物，公开捕获也没有覆盖它的按键写入、完整档位表、所有原厂功能或本项目 UI 品质。当前仅完成上述协议基础修正，不能作为新增完整适配发布。
