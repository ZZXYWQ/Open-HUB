# COMPX 原厂有序快捷序列、文件往返与 UI

静态核对发现原厂组合键UI先抬起修饰键，再抬起主键；此前单键组合解析会拒绝此原厂顺序。现增加完整有序事件动作，既不丢弃这些记录，也不把顺序改成另一种组合。原厂宏库正文迁移仍未完成。

## 实现

共享模型新增带类型的 Shortcut 事件数组，每条保存种类、按下/抬起和原始值。支持已核实的修饰位分组、普通键盘、五种鼠标输出和七种媒体用途，2–6条完整平衡事件；同类型的按下/抬起严格匹配，拒绝重复/未释放输入。电源、移动、滚轮、扩展字节和未知媒体记录仍拒绝，不造默认动作。

驱动读回完整表后保留分组与顺序。只有重新编码与全部原始记录完全相同的标准单键组合才显示为旧Key动作；其他内容保留新Shortcut类型。文件从固定实体defaultKey和shortcutAction正文转换，同样不依赖名称/显示顺序。序列原生写入32字节class5表，无宏槽、无主机输入或新增延时，继续使用完整表/当前组绑定快照及条件恢复。

新类型只准入既有精确COMPX型号和已登记非左键。配置验证和单独编译入口均拒绝其他品牌/型号；Pulsar仍用其原协议。赛睿底层明确拒绝新动作，其他现有JSON动作保持原样。

UI包含逐条类型、状态、键值/修饰位分组、上下排序、添加和删除，显示原厂释放顺序。导入预览逐项列出事件。保存仍由后端验证完整平衡，未平衡输入不会写入或保存为可用配置；编辑器可以保留临时未完成的编辑状态。
