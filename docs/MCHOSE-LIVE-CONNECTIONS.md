# 迈从当前连接与草稿隔离

开发分支增量，尚未发布或安装，不增加完整型号计数。

之前迈从控制中心仅用设备路径与板载组发出请求；接收器重插或传输重新打开后，路径、型号和板载组可能仍相同。现在设备列表为迈从提供当前 `connection_key`，首次读取必须核对这个连接；原生读回结果另带 `target.device_key` 与 `target.connection_key`。

`device_key` 来自设备管理器当前原始归属，不取配置中心可能解析出的持久别名。连接标记只表示本次传输，不保存到用户配置归属，也不写入可携带的板载备份或宏文件。它不等于接收器所配鼠标的硬件序列号。

宏读取、按键/性能/DPI/宏保存、完整备份导出及恢复都携带读回的目标，原生端在设备管理器锁内、任何 HID 请求或文件处理前核对。归属、连接、厂商、接收器编号或已知型号不符时拒绝，不自动把旧请求改为当前连接。无上下文的通用手动 DPI/回报率/板载命令不再用于迈从；独立配置应用仍使用原有新鲜设备路由，其他品牌沿用各自逻辑。

回报率按钮改为带相同目标与预期板载组的 `report_rate` 动作。保留原始设置两个低半字节、完整 XY 六档、其他参数与其他板载组；写前完整备份，随后写入并回读。操作期间实体切换板载组仍会报错，多条固件命令不据此获得原子性。

界面以设备路径和连接标记共同决定面板生命周期。新连接重新读取，旧 DPI、性能、名称与宏槽草稿不继承；离开面板时布局阶段清理异步归属，旧文件对话框、读取或保存回执不能继续更新新连接。相同连接下读回的原始归属改变也不能替换已有草稿，错误保存回执不能确认或清除草稿。

## 验证范围

默认原生测试覆盖旧连接/原始归属/型号拒绝、无 HID 和无备份副作用、完整读取结果的目标与备份分离、六种回报率的完整状态保留、错误回报率及切组竞争。实际构建的 React UI 使用独立 IPC 模拟器，覆盖跨设备与相同路径重连、延迟成功/失败、文件对话框、旧草稿清除、缺失连接及错误回执。界面采集的按键、宏与重连前后回报率请求另外经过生产协议与原生模拟传输回放。

完整结果与源文件摘要见 [验证记录](development/2026-10-27-mchose-context-validation.json)。模拟替换的是物理 HID I/O，不代表当前固件已实物验证。
