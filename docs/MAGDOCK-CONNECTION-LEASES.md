# MagDock 灯效连接与原生模拟

开发分支增量；没有写入实体底座、更新安装版或新增完整鼠标型号。独立 MagDock 的功能不能计为鼠标本体 RGB。

## 原厂协议范围

固定渲染器的[静态事实](development/magdock-static-protocol-facts.json)给出 GET7、SET39、RGB 流41、十个设置字段、读取方向的独立 offset29，以及原厂六种模式。普通设置的 modeNum 默认值是5，即使界面有条件显示第六个音乐项，也不能强制改成6。

原厂 mode 和 lightSyncStatus 是两个独立字段。本次原生读取保留基础 mode，而不是看到 sync 就改写为5；界面用 sync 展示音乐选项并正确调用软件律动，旧基础模式继续保留供恢复使用。睡眠开关/时间只读字段没有被写入，未知能力未开放。

底层 Session 接入可替换 I/O，测试直接使用生产解析、写入、读回、控制器及动画 Engine。独立手写响应向量按原厂 offset 编排，未从生产 setter 反推，也不是实际固件抓包。六种模式核对精确十字段与读回；12 颗灯珠核对逐 RGB 顺序。

读取校验声明长度、完整正文、已支持单帧头及状态范围；拒绝截断或未知状态。排空旧报文有32次上限，持续报文不会无限阻塞。测试允许带/不带0号 report ID；严格实现范围不等于所有固件响应都已支持。

## 任务生命周期与恢复

每次打开底座生成单独连接标记。动画 Engine 的开始返回 StreamLease，逐帧、停止恢复均使用该标记；音乐线程也捕获开始连接。断连或传输失败会结束旧任务，清理不再自动打开其他底座。即使另一个只读请求已打开新 Session，旧任务也不能给新底座发帧、恢复设置或使新 Session 失效。

备份使用 create_new、完整写入与 sync_all，在首次 SET 前完成；动画启动在备份后再次读取原状态。恢复先核对当前设置仍等于任务设置；若其他程序已改动，拒绝覆盖；若已经恢复，仅读取。设置失败不再进行不确定的自动覆盖恢复，保留备份并报告可能部分生效。诊断自测也固定在一个打开的句柄上，出错后不会重新打开另一只底座恢复。

目前主界面只能选择一个 MagDock。枚举若发现多个匹配接口会拒绝任意选第一只，多底座明确选择 UI 尚待开发。这是过渡期限制，不代表逐底座完整支持。

## 验证与缺口

新增14项默认原生测试覆盖独立报文、六模式、颜色流、短写、读回不一致、断连后清理、新旧连接隔离、外部改动、备份失败和正常恢复。包含实际静态效果 Engine 线程向生产内存 Session 发帧并恢复，未启动音频采集或屏幕取色。19项构建界面测试覆盖电脑 RGB 与底座独立操作及 mode0+sync1 的音乐呈现；其后端是有状态 IPC 模拟。

仍待完成：手动底座写入 IPC/动画启动对 UI 预览连接的绑定、多底座选择与 UI 草稿隔离、音乐线程的模拟音频输入及真实音频/屏幕/LED 对照、恢复/备份文件的完整用户入口和实机验收。此增量只证明已开始任务的连接生命周期，不宣称全部灯效界面请求已经绑定连接。

原厂 Ff 默认生成63字节 WebHID data，现有 HIDAPI 实现保留65字节（含ID）写出；有效头/载荷已核对，末尾 padding 尚需设备描述符与真实报文对照。本次没有据模拟去改动或宣称这个物理长度已得到证明。0/100 完整验收数保持。
