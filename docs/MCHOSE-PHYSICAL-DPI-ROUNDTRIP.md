## 实际暴露的协议差异

直接请求非当前组的 `0003` DPI 表时，这台固件仍返回当前组及其编号。实机曾对 0/1/2 三组、X/Y 两轴分别读取；在当前组为 0 时，六次响应均属于组 0。严格的编号校验保留，不把响应改标签冒充其他组。按键 `0001` 的三组读取则返回了不同记录，当前组自定义动作与其他组默认动作区分明确。

原厂静态 `MJ` 按当前组读取 DPI，`au` 通过 `0906` 选择工作组。新增的显式切组诊断先保存原组，再临时选择各组读取真实 DPI，最后返回原组；它不是正常读状态时偷偷切组的退路。普通用户读写仍绑定当前组。

联动 XY 的另一个差异由实机发现：旧实现总是依次写 X/Y，而原厂 `Yv` 在未启用独立 Y 时只写 X。本次旧顺序试验未得到期望值；修正后只写 X 的试验实际读回 X/Y 均从 1600 变为 1650。对这组已观察固件，联动状态的六档 Y 随 X 镜像；不能把此前仅在模拟设备里保留的不同 Y 表当作本固件事实。

原生写入现按精确固件组合处理联动镜像；独立 XY 继续分别写两轴，其他固件不被直接套用这一观察。便携 M HUB Plan 中暂未启用的 Y 设定仍保留在文件，编译到该固件时显示/核对实际镜像结果。精确备份若声称联动状态却有不同 X/Y，恢复预览在 SET 前拒绝，避免悄悄丢掉不能精确还原的数据。

## 原厂空名称

实物三组名称为空。原生完整备份允许这类原厂状态，而普通 M HUB 模板要求非空名称；此前将两者使用同一校验，导致备份恢复编译被拒绝。严格原生备份现有独立编译入口保留空名称，普通模板的名称校验保持原规则。本次实机没有重命名；非空名称恢复成空名称另经原生内存事务模拟验证。

## 实机结果

最终试验实际完成 **1600 → 1650 → 1600**，当前仍为原组 0、活动索引 3。观察到测试值后执行反向恢复；返回原组读取的完整原始参数、三组 X/Y 表、三组六键记录和宏内容与开始前一致。十八个宏槽均读取，当前为空。另用独立 Node HID 编码器/读取器 GET 当前 X/Y，确认字节与原值一致。

前面三次探索未被算作成功：第一次因非当前组响应编号不符而在 SET 前停止；第二次切组读完并返回原组后，因空名称校验在 DPI SET 前停止；第三次旧双轴联动写入未通过回读，完整原状核对成功但试验标记失败。最终第四次的 `observed` 与目标完全相同，`after` 与完整 `before` 捕获完全相同。

每次使用新诊断目录，避免把观察超时当作重发理由。不可变原始文件和持久备份在首次写入前保存；仅在新鲜状态仍属于本次修改时恢复，外部配置、宏或板载选择改变则停止覆盖。显式切组失败只撤回本次已发送的选择，不重放其他组参数。正常启动不执行自测，不启用其他品牌接收器、不控制桌面、不触发按键或宏、不发送固件/DFU/复位命令。

最终监视器等候超过 45 秒时没有重启诊断，继续检查原 PID，随后确认进程不存在、结果和前后文件完整；退出码没有被捕获，不能虚构退出码零。软件返回 `passed=true/restored=true`、实际中间状态及独立 GET 才是本批成功依据。原始本地文件保留，公开测试夹具清除名称，且明确区分原生解码快照与完整 USB SET 抓包。
