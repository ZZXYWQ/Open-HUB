# 原生预览的连接校验

开发分支增量，尚未发布或安装。解决同型号、相同 unit-id 的设备重新连接后，旧预览仍可能被提交的问题。

配置归属继续使用稳定的 unit-id 或明确的会话范围；不会因为重新插拔而把原有独立配置重命名。另有一个连接标记，在重新探测设备或重新打开传输时生成，保留的活跃设备沿用。它只用于当前读取/修改流程，不作为持久配置归属或硬件序列号。

板载快照和原生灯光视图携带这两个值。按键、DPI、宏查看、宏预检查/提交、灯光和备份恢复请求必须同时核对。旧连接请求在任何 HID 通信前被拒绝，即使型号、USB 路径、unit-id 和原始数据碰巧一致。已准备好的宏事务也不能转到新连接继续提交。

宏编辑器提供“重新读取鼠标，保留草稿”。只有读取结果仍属于原来的配置归属，才更新连接和原始按键记录；宏名、事件和修饰键保留，之前的预检查作废。读到另一只鼠标时不自动改目标。重新检查仍会核对全部存储和空间，不会直接重发旧写入。

板载写入 CLI 也只接受唯一的合格直接 USB 罗技鼠标；同时连接多只时不再选择列表中的第一只，用户可在界面选择具体设备。接收器、键盘和其他品牌不混入这个写入目标集合。

四项新增默认测试覆盖旧连接的按键/DPI/宏/灯光零 HID 拒绝、新连接保持相同配置归属、旧宏事务不可转移及 CLI 目标歧义。新界面测试覆盖错误设备刷新拒绝、同归属显式刷新保留草稿、重新预检查与新连接的生产宏提交回放。

当前 469 项默认应用测试、20 项显式交叉测试和全部 34 套无头界面回归通过；开发 EXE 的 32 个内存传输自检通过。没有新增鼠标实机操作或完整型号验收，没有生成安装包，已安装 0.3.7 保留。无线重新配对仍不因一个 USB 连接标记而得到物理身份保证；此前关闭的接收器写入不开放。
