# 迈从共享宏的独立编辑

2026-10-27，开发分支增量。适用范围仍为已注册的 A7 V3 Ultra+ 协议；没有因此增加完整兼容型号。

## 实际接通的行为

三个板载组共用十八个宏槽。原先实时面板直接写入用户选择的槽位，可能同时改变其他组引用的宏。本次将实时保存接入独立的宏编辑编译器和已有完整事务提交器，原生命令入口与 `apply_hardware_for` 都经过这条路径。

保存前读取当前完整状态、宏正文和三组按键引用。所选槽仅属于本组或没有其他组引用时，保持用户选择的槽；原内容相同时无需重复写入。若其他组引用原槽，则保留原宏，优先复用相同字节的已有宏，否则分配没有正文且没有任何组引用的空槽。只更新本组中原来引用该宏的按键；本组没有引用时，仅保存新宏，不凭空绑定按键。

未绑定的现有宏也不会被当作空槽；只有引用但正文为空的槽同样不能占用。其他组含未知动作时，不能假定它不引用宏，因此阻止新分配；仍可复用已经存在的完全相同内容。没有安全槽会报错，不先覆盖原宏或新建备份。

事务在首个 SET 前持久化原像，并重新核对状态、全部组引用及目标槽。先上传并读回宏，再更改本组引用；每段上传都会检查组选择与三组按键引用。检测到外部改动、读回不匹配或传输失败即停止，错误保留备份路径，不自动重试或恢复。宏为设备原生数据，未使用操作系统输入注入。

## 界面

保存回执携带实际槽位及读回所对应的完整宏。面板切换到实际保存槽，并显示“共享宏已保存到宏槽…”；之后再次读取源槽仍得到原宏。源槽提交时的草稿清除，不把新内容误标为已保存在旧槽。目标槽已有未保存草稿时保留草稿，同时更新其已核对基线；提示区分别显示保存结果和未保存状态。设备切换、重挂载或重连后的旧回执不能填入新面板。

## 尚未证明的部分

本批没有实机宏写入、按键触发、四种播放模式、宏断电保留或固件暂存中断行为的证据。GET 与 SET 不是原子事务，外部写入的竞态仍不能被完全排除；中断上传可能留下暂存数据或已完成的部分修改。其他组的引用不能被主动改写，这不代表软件能阻止其他程序主动修改它们。
