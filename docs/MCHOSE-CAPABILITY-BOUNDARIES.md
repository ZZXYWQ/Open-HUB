# A7 V3 Ultra+ 的自动省电能力边界

开发分支增量，尚未发布或安装。此前将 A7 的自动省电回报率列为待补功能；本次核对原厂能力门槛后，改为当前原厂构建下“不适用”。这不影响普通休眠、永不休眠或用户设置的回报率。

## 原厂证据

[静态 AST 事实](development/mchose-adaptive-capability-official-facts.json)对应已认证的公开渲染器 SHA-256 `c3e91c2828283cbcb8edb24474b45d64b2526bcbed0a2740919a0deef7ad61bc`。能力名单只有 `MCHOSE K5 Pro` 与 `MCHOSE K5 Ultra`，并分别带原厂固件门槛字面值 `13`、`12`。没有据此推断字符串的十进制版本含义或启用 K5 型号。

完整信息读取、方案恢复、连接初始化、板载切换和界面计算能力的五处引用都读取这份名单。设备名称归一化只去掉 `RealTek`、`YJX-CHIP` 前缀，不把 A7 转成 K5。因此当前 A7 不应要求 `000A` 读回成功，更不能仅凭一份诊断响应就开放 `010A` 参数写入和 `010B` 省电心跳。

名单内型号的原厂主机逻辑区分游戏模式 0 与非游戏省电模式 1，进入时立即发送心跳，省电期间每 30 秒维护一次。该逻辑不是 A7 当前的原厂功能；本轮没有把它复制到 A7，也没有新增 K5 的 USB/型号身份或兼容计数。其他固件或后续原厂构建需要新证据。

## 读取与备份

A7 读取当前配置和自动备份时不再发送未开放的 `000A` 请求，也不发送 `010A/010B`。普通六档 XY DPI、回报率、按键、宏、LOD、休眠、消抖、传感器设置和板载名称的原有读取继续执行。性能页明确说明自动省电回报率的边界，普通休眠仍可编辑。

新完整备份使用 `mchose-v3-full-v3`，`state.adaptive` 为空，表示当前型号没有这项可恢复能力。旧 v2 中空值或已经捕获的默认诊断记录 `[0,0,3,0]` 可迁移；它们不变成可写能力，也不发送省电命令。v2 的其他值、长度、启用状态及任何 v3 非空记录会在 HID、写入和新备份之前被拒绝，避免把不能还原的字段悄悄丢掉。备份型号、原始设置、DPI 和按键一致性校验继续保留。

新增原生测试使用当前生产编解码和状态传输：模拟器对三条未开放命令直接报错，验证完整读取、新格式完整往返、旧默认记录迁移以及未知记录零通信拒绝。既有按键、宏和逐连接回放继续覆盖，实际结果见 [验证记录](development/2026-10-27-mchose-capability-validation.json)。没有实物省电播放或参数写入证明。

## 剩余工作

这次修正关闭了错误列入 A7 的省电能力缺口，不表示 A7 整机通过验收。逐鼠标物理身份、真实宏播放和固件行为、完整 M HUB 内容转换及其他原厂功能仍需继续核对。100 种完整型号目标与已安装 0.3.7 保持原状态。
