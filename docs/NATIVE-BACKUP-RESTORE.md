# 原生板载备份恢复：开发增量

尚未发布、未安装，不增加完整兼容型号数量。本轮只针对已知 HID++ 0x8100 直接 USB 鼠标的板载备份恢复；不把接收器或其他品牌的相似文件作为可写数据。

选择文件后先走同一原生模型/布局检查，再解码原始扇区显示槽名、DPI、回报率及启用状态。预览不采用 JSON 中可能过期的解码摘要。配置名依据 24 个 UTF-16LE 字符单元解码，支持中文和代理对；非法序列保持未命名，不替换原始数据。

恢复要求 Open HUB 备份格式、至少一个确切鼠标型号 ID、相同内存模型/配置格式/宏格式/槽数/按键数/扇区几何/机械布局。检查实际 CRC、重复扇区、缺失目录及引用、越界和别名；先读完全部待改扇区的现状，再进行写入。CLI 的文件备份同样包含这些元数据，恢复前保存独立的原状文件，多个候选鼠标不会自动选第一只。

预览对文件原始字节计算 SHA-256；保存时重新读取并比较，文件有任何改动都要求重新选择和预览。当前连接和鼠标配置归属也必须与预览一致。界面失败后清除旧预览，不允许直接重试旧数据。已经写入并读回校验的恢复与随后刷新界面失败分别反馈。

当前恢复范围是目录及其引用的用户配置扇区，目录最后写入；ROM 和未引用扇区不写。备份里含有原生宏引用时，预览明确显示数量及宏存储尚不恢复的范围。此范围不是完整闪存恢复，多扇区事务恢复仍在继续开发。旧的缺少型号或布局元数据的诊断片段不能当作恢复文件。

SHA-256 复用更新器依赖图里已有的 sha2 0.10.9；增加直接引用，没有新增锁定包或分发厂商运行库。界面继续复用现有对话框和组件。

名称字段依据独立参考工程 [cvuchener/hidpp ProfileFormat.cpp](https://github.com/cvuchener/hidpp/blob/474ac10db5673da8f2f1c8911414d394c0eb6d12/src/libhidpp/hidpp20/ProfileFormat.cpp) 核对。生产方法通过 FeatureRequest 内存传输测试，并以原生导出 DTO 驱动隐藏浏览器，再将实际界面恢复请求送回生产方法验证；没有接触罗技实物，也没有执行模拟鼠标输入。

## 多扇区事务与 DPI 保存

恢复现在先捕获每个目标扇区和当前目录，复读核对后生成只读计划。Tauri 与 CLI 保存该计划的确切写前数据并同步文件，再进入提交；备份会包含新目录引用但当前目录尚未引用的目的扇区。每个扇区提交前后重新核对选定内存、目录、完整内存描述和鼠标/连接身份。目录最后写入，已经相同的扇区不重复刷写。

一次操作后段失败时，只有当前各扇区仍分别等于写前或本次目标值，才撤回本次所有已改扇区并核对完整原状。不同值、不同目录、不同描述或换鼠标都会阻止盲目恢复。54 个三扇区失败阶段（开始、48 次数据块、提交）均由生产 FeatureRequest 模拟；也覆盖目的扇区原状保存及第三方修改。仍不是硬件原子提交，未知的部分写入不会被伪装成成功或盲目重试。

板载 DPI 保存复用该事务，在计划时再核对最初读取的目录和 DPI 扇区。18 个不确定写入阶段、外部目录变化及过期描述经过模拟。删除旧的无条件写回帮助函数。

成功后仅当鼠标原先已处于板载模式，且当前启用槽确有变化，才重载该槽；不切换软件模式或另一个槽。已校验保存与当前槽重载失败、完整视图刷新失败分别反馈。界面清空无法刷新的快照，并保留保存成功的提示。当前仍仅恢复目录与用户配置，宏存储、ROM 和完整 OEM 配置导入没有因此完成。
