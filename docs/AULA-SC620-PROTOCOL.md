## 已实现

- 64 字节原始中断帧、65 字节 Windows 输出缓冲。发送校验值为报告字节 5..64 的和模 256，写在报告字节 4；对应官方程序 `43A450..43A484`。
- 有限类型的只读诊断查询：03/00 身份、08/A5 按键页、0E/A5 配置页。没有任意命令入口；0D/00 是写宏内存命令，绝不当作读取。扫描不调用诊断查询。
- 严格响应长度、命令、子命令、地址、页面和载荷长度检查；先清理有限数量旧消息，跳过完整异步事件，查询只发一次。短写、短读、错误页、持续占用、超时均报错。响应校验算法尚未证实，不虚构 CRC 验证。
- 46 字节配置镜像，六档 DPI、当前档位、六档指示颜色的选择性修改和完整输出编译。DPI 按官方无符号边界检查为 50..26000；步进尚未确认，不静默量化。回报率、传感器位、未选择的灯效、保留字节均保留原值。每档指示颜色不等于完整 RGB 灯效。
- 七个官方灯效枚举：波浪、霓虹、循环闪烁、YOYO 球、单次闪烁、呼吸循环、关闭。官方语言编号 531..537、菜单项 0..6、选择索引到 `light_mode` 再到配置载荷字节 1 的链路已逐处核对；未选择时保留未知灯效编码，不伪造可调亮度/速度。仍只有报文编译，没有灯效实机验证。
- 六个按键读取页，每页 44 字节、11 条四字节记录；原厂整库写入循环仅覆盖前五页。鼠标五键、双击、滚轮上下、DPI 循环、组合键及八种媒体动作的编码与解码；八个左右修饰键位均保留。按键修改要求原始四字节一致，不接受重复记录。未知动作、宏指针和其余页面不转成默认值。EEPROM 记录序号尚未标作完整物理按键布局。

配置和按键只有纯报文编译器，暂没有真实写入执行器。要接入实机，仍需型号/单只设备身份固定、页面实际回读、写入恢复及物理按键布局证据；不能用模拟通过替代这些条件。

## 2026-10-27 宏内存增量（静态编译，未接入设备）

新增独立宏内存编解码模块。固定 64 字节偏移表、最多 32 个连续库项、总缓冲不超过 0x1080 字节；每条事件四字节，由原始延时字段和动作组成。已表示普通键按下/释放、五个鼠标键按下/释放及正反滚轮。偏移、边界与最终标记严格校验，未知动作保留原始内存，读取时不转换为默认动作。

本次纠正此前私有研究笔记的结束记录描述：原厂 429D77 仅在空事件列表跳到 42A15F，写 `00 00 80 00`；非空列表的 429FCD 跳过这段。非空宏的最后事件标记 bit7，末尾延时路径则在前一条记录上补此标记，**不能给每个非空宏再插入空结束记录**。新增黄金向量同时包含非空、空和非空三个宏，核对完整内存与全部输出缓冲。

0D/00 的 56 字节分块、低字节先行的内存偏移、尾块长度和填零、最终 10/A5 报告均只编译为数据，复用已核对的发送校验和。此模块没有调用任何 HID 传输，也未加设备入口或注册共享 VID/PID。它生成新完整库的静态镜像，**不是在现有设备宏库中安全合并、恢复或写入的执行器**。读取格式仅接受已核对的原厂紧凑布局，不把未知设备内存尾部当填零删除。

延时仍作为 `delay_raw` 原字段保存，不宣称已经测得时间单位或等价播放。汇编中的宏键转换调用 43CD80，而按键配置使用的修饰键位转换是 43D390；两条路径不能直接等同。此次未开放宏修饰键类型，1/41 等记录保留不透明；鼠标移动事件、宏绑定/次数、原厂事件列表转换和完整键码映射继续核对。

新增 **9 项默认测试**：独立全内存/全报告向量、支持的键盘鼠标滚轮编码、0x1080 容量及跨 256 字节偏移、32 项上限/空库、未知动作保留、坏偏移/结束标记拒绝、非法动作拒绝、JSON 原始延时边界，以及未明修饰键的无损保留。主程序全量 **862 通过、0 失败、68 忽略**，非测试构建通过。没有本批界面改动、实机读写或安装包，完整型号验收仍为 0/100。

## 2026-10-27 宏绑定和整库引用增量（仍为静态编译）

原厂 4112B8..4112EF 写出 `70 / 库项索引 / 重复字段 / 模式字段`，索引与宏库列表的零基顺序一致。已核对模式码 0、2、3：码 0 保留非零重复字段，2/3 对应字段固定为 1。该程序未核对到足够的模式 UI 标签，因此内部使用 `Code0`、`Code2`、`Code3`，不把 W12 的“按住/任意点击停止”等标签套到 SC620。`Code0 repeat=1` 也不宣称等于执行一次。非零字段值域来自单字节表示及此静态写入路径，不是实测循环次数范围。

新增独立宏绑定类型，范围限定 32 个库项；基础动作 `Action` 仍不接受任意宏编号，必须带完整宏内存镜像校验目标库项存在，再修改预览中明确选中的四字节记录。无效编号、重复选择、旧四字节不匹配或缺失目标库项拒绝，不用默认宏填补。

整库静态方案编译要求六份有序读取页及修改前/后的完整宏库。未选中的每个原厂宏绑定必须继续引用同一索引下逐字节相同的宏正文，包括第六页、共享引用和不透明宏正文。无法解释的 0x70 记录会阻断宏库整体替换；只改绑定且宏库完全相同时可保留不透明原值。已选记录的修改不豁免其他引用保护。需要上传宏库时，输出完整宏数据分块与结束报告，再输出有差异的已核对按键页；没有任何差异时不生成报文。

本次纠正“读取六页等于可写六页”的边界：原厂 42925B..42930D 读取 0..5；42A48E 从 1 开始循环，以 `ebx-1` 为页，42A5F9 比较 6 后按有符号小于继续，因此仅写 0..4。按键页的基础修改、宏修改与输出编译均拒绝第六页写入；它仍参与全库引用校验。这里的 55 个可修改 EEPROM 记录**不等于 55 个物理按键**，实际控制映射继续核对。

新增 **10 项默认测试**，包含全部 32 索引与 255 个非零重复字段的编解码、模式保留值拒绝、独立完整整库/结束标记/两页输出向量、其他页及第六页引用保护、共享宏逐引用核对、不透明绑定、旧值/重复/页序拒绝、悬空索引、第六页写入拒绝、零差异以及 JSON 格式边界。SC620 模块共 **35 项通过**；主程序 **872 通过、0 失败、68 忽略**，非测试构建通过。

没有新增 HID 执行器、自动识别、文件格式/UI 入口、实际设备读取/写入/恢复或安装包。这里的“事务”仅指全部预检完成后生成的有序报文；不代表设备原子提交，也不保证发送中断后的安全恢复。型号身份、实际宏播放、完整物理控制对应、官方文件转换及 UI 仍是接入门槛，完整验收仍为 0/100。
