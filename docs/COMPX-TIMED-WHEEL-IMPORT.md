# COMPX 原厂滚轮宏与两段时序

2026-10-29，开发分支；不新增型号或完整兼容计数。

依据[固定原厂静态来源](development/2026-10-29-compx-file-scroll-source.json)，本轮核对的是 COMPX 的 ko.setMacro（位置2115264），不是同文件前面其他协议类的同名方法。原厂录制器保存正数滚轮幅度和明确的上/下状态；COMPX 写入器忽略幅度，每个源事件写成一条方向记录和一条归零记录，两条分别使用源延时。固定版本的空传感器延时表令零延时实际写为1ms，两条均如此。

导入器现在转换这种明确的录制库事件。37ms的向上事件保留为方向37ms、归零37ms，而不是改成1ms方向或只留37ms总延时。257ms向下事件保留两段257ms，采用大端时长；不会按滚动幅度重复输出。有效正数幅度限制1–65535。零/负数/小数幅度、普通按下/抬起状态、超时或展开后超过70条原生事件拒绝整份已选按键转换。明确排除按键范围后仍可仅导入DPI。

原厂getMacro把每条原生滚轮记录分别导出，向上可能产生负数键值，归零0又被标成向上。此类文件缺少明确的录制事件边界，本轮继续拒绝，不猜测合并或多扩成一次滚动。电源、移动及不可准确表示的媒体保持仍未转换。这不是任意原厂宏文件无损迁移。

新增严格序列化的ScrollTimed，包含方向、脉冲和归零毫秒数。脉冲2–10000ms，归零0–10000ms，累计延时仍限60秒。脉冲1ms继续使用原有Scroll加Delay格式，旧JSON保持不变。原生编解码保留两条五字节记录及校验，追加Delay会累加归零时长，超出可回读上限拒绝。软件播放层若收到该已验证通用事件，仅产生一个滚轮tick并等待两段时间，不把归零当额外滚动。原厂文件路径仍编译成鼠标原生宏。

导入确认页显示方向及两段时长。板载宏编辑器提供方向、脉冲、归零独立控件，可新增定时滚轮；名称和逐键单次/重复/按住/切换模式继续保留。相同正文可共享原生槽；仅修改某一绑定的宏正文后，该绑定分配独立槽，其他绑定不变。

验证包括独立完整报文向量（两个方向、四种播放模式、多字节延时）、严格JSON边界、延时扩展/溢出、十连接文件解析与保存往返，以及较长正文最后数据段和绑定段发送前后失败恢复。测试故障仅作用于隔离内存传输，没有访问USB或注入系统输入。

当前React在无头Edge保存十份原厂导入，再分别编辑并重新打开，共20份方案、40个宏绑定；真实保存请求经生产配置校验、编译和内存原生驱动回放，核对所有事件、两段时长、模式及共享/独立槽。IPC、设备目录和文件对话框模拟。截图已检查；原有键盘宏十份导入回归通过。
