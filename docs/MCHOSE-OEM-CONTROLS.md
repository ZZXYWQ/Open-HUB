# 迈从 V3 原厂可选按键动作核对

开发分支增量，未发布或安装。范围是现有 A7 V3 Ultra+ 路径使用的固定原厂 V3 前端；不是 169 种鼠标，也不增加完整型号验收计数。

## 来源与本次修改

[原厂静态事实](development/mchose-v3-selectable-actions-official-facts.json)来自同一份已认证渲染器 SHA-256 `c3e91c2828283cbcb8edb24474b45d64b2526bcbed0a2740919a0deef7ad61bc`。Babel AST 只提取九个实际按键选择表中的字符串字面值，不执行原厂代码。去除语言别名及重复值后得到 169 种不同编码，保存在测试专用的 [独立向量](../src-tauri/tests/fixtures/mchose-v3-selectable-actions.json)。这些测试数据不进入产品安装资源。

普通键盘表 `VJ` 明确给出左右 Ctrl/Shift/Alt/Windows 的 `11 00 E0..E7` 形式，经原厂字节序规则写成 `11 E0..E7 00`。此前只凭宏用的 qM 表没有开放普通侧别修饰键；本次有独立 VJ 证据，实时面板和完整方案编辑器都可选择这八个独立按键。组合键仍使用四个通用修饰位，选择独立侧别修饰键时会清除并禁用组合掩码，不虚构八位左右组合格式。

原厂 `Xbt`/`Obt` 还明确列出停止播放 `14 B7 00`、屏幕亮度加 `14 6F 00`、亮度减 `14 70 00`，已补入两处使用的共享动作表。这是主机消费控制按键，不是 RGB 灯光亮度；实际显示设备是否响应还需实机与系统验证。

新建“全选”改为 VJ 的 `13 01 04`。早期 Open HUB 的 `16 01 04` 不再作为新预设提供，但已有记录显示为“旧版全选编码（保留）”，保存时不会自动改写。复制、剪切、粘贴继续使用原厂明确给出的 type16 预设；用户也能构造 VJ 的 Ctrl+C/X/V 组合。

完整方案编辑器对非键盘动作显示主键占位项，让 A 键能直接选中；不再把辅助控件的默认 A 显示成现有映射。type12 仅修饰键会正确恢复为“仅修饰键”，其余 DPI、性能、宏正文、板载名称和应用关联保持原计划。

## 覆盖范围

[验证记录](development/2026-10-27-mchose-oem-controls-validation.json)区分以下证据：

- UI 真正使用的 TypeScript helper/preset 对照独立 169 项字面向量，全部可表达；每个新建非宏预设也必须出现在原厂集合中，避免单向“有入口”检查。
- 全部 169 项从完整原厂字段转换为 Plan，再走生产逐设备完整方案与差异写入路径，核对原生按钮字节、读回、其他板载组、另一只鼠标零通信和已有宏不重复上传。
- 构建的实时面板产生 120 次实际 IPC 请求，覆盖 104 个普通键盘用法（含八个独立修饰键）、通用组合、仅修饰键、媒体/亮度、剪贴板和第二只鼠标。请求再经两套隔离生产内存传输回放。
- 完整编辑器通过真实 Rust 准备函数保存 15 份方案：旧全选原样保存、直接选择 A、八个独立修饰键、三个消费控制、正确全选、仅修饰键。完整载荷再走生产差异事务回放，另一鼠标不通信。
- 既有完整导入/编辑、当前连接生命周期和罗技逐鼠标路由界面继续回归。以上替换的是物理 I/O；没有实际按下鼠标、调节系统亮度或注入输入。

169 项仅是该固定选择表的闭合集合。动态宏槽、通用组合、其他原厂版本、固件/产品限制和实体输入效果不能据此全部认证。原厂通用长度编码器提及的 `22/23/24` 在这九个选择表没有对应字面写值，语义仍不确定；存入模板的这类记录继续拒绝，不能把缺少映射误说成固件必定不支持。

## 灯效与剩余工作

同一原厂源已确认独立 `MCHOSE MagDock`（`3837:1012`）使用读取 7、设置 39、逐灯珠流 41，六种界面模式分别为常亮 0、呼吸 1、闪耀 2、循环 3、流动 4、音乐 5；音乐项带原厂条件可见性判断，不能据此认为所有环境均开放。这个独立底座路径不能证明鼠标本体有同样的可写 RGB；本次按键补充没有新增灯效实现或灯效验收。
