# SC620 原厂宏事件到原生库的静态转换

## 来源和键码

重新核对同 SHA 的官方安装包，仅提取原程序进行静态检查。此前保留的反汇编中 43CD80 转换函数的比较、返回值与选定延时/事件指令逐条对照原始机器码。独立 fixture 记录 109 个能明确转换的原厂键码，覆盖字母、数字、F1–F24、已核对标点、导航和数字键盘；包括原厂特殊的 0x29A 输入，不把它截成一个字节。

普通键按下/释放分别写原生类型 42/02。修饰键的源编码分支尚有不一致，不能复用基础按键的修饰位掩码；这些来源值继续拒绝。未知键不转为键码零或默认 A 键。

五个鼠标键按下/释放和显式滚轮上下已转换。原程序中按描述覆盖动作的两个常量经原始数据段确认是区分大小写的 `Scroll Up` / `Scroll Down`；上下两个字符串同时存在时按原厂顺序先匹配 Up。转换保留这条规则，不根据翻译后的描述猜测滚动动作。鼠标移动和未知事件尚不转换。

## 延时和整库边界

原程序从 SQL 的 `value` 列读到事件对象 +10，原生延时编译使用这个字段；SQL `delay_time` 列在对象 +14，两者不能互换。原始列、宏的 delay_type/delay_time 元数据仍保留在只读预览中。

延时行累加到前一条动作的两个字节。下一动作到来时累计为零，原厂写默认 10；末尾延时则保留实际累计值，包含零。仅按原厂字节编译，不宣称这些字段已经通过实物测得时间单位或播放效果。前置延时会被已核对的原厂编译器丢弃或写入头部，故本程序明确拒绝；超过 16 位的单次或累计值拒绝，不截断。

还有一个跨宏规则：游标贯穿全库，但每个宏的延时累加器重新置 1。后续非空宏的第一条动作会把前一宏末条记录的延时低位 OR 1。例如 50 变 51；若前一宏为空，其结束记录也可能带上延时 1。这次完整库转换精确保留该原厂输出；不能只把每条宏独立编译后拼接。带延时的空结束记录在原生类型化读取中继续作为不透明内容保留，不把它重写成零延时。

## 转换和配置链

转换为新完整宏库时，输出显式的原厂 macro_id → 新 0..31 槽位及播放方式映射。调用方选择的库顺序决定新槽位；ID 7/42 不直接当成槽号。重复 ID、模式元数据不一致、事件序号重复、超容量和任何不支持的事件都会让准备整体失败，不默默省略失败宏或事件。

这是离线新库转换。若要取代设备当前库，仍必须经过既有六页引用校验，保护其他按键、其他页及不透明原厂引用；本模块不绕过这条门槛。它没有设备读写、型号辨识、连接绑定、落盘备份或恢复能力，不能直接应用到鼠标。

## 2026-10-27 移动事件原生编码增量

原厂类型 8/9/10/11 都将源值低字节复制到原生 46 事件的载荷；类型 12 将两个源字节的低四位合并成载荷，并将两字节各自最高位转换到前面原始字段的 0x4000 / 0x8000 标记。本批根据固定 SHA 的保留反汇编逐指令核对；没有新增下载或原厂程序执行。

新增 `Motion { packed }` 原生类型，完整保留两字节原始字段。记录读取不再把已核对的 46/C6 全部视为未知；其余未知事件仍原字节保留。这里的轴标记只按位表达，**没有赋予它们正负方向或距离单位**，也未使用 W12 的极性结论。只有实际 SC620 固件测试才能确认哪一位对应向左/右/上/下、移动距离和最终事件执行方式。

原厂 SQL 源类型 8..11 支持字节及其标准有符号表达，类型 12 支持双字节及其标准有符号表达；超过该原始字段的值拒绝，不截成可接受值。类型 12 中未参与原厂载荷的源位仍在数据库预览数据里保留，不宣称能由原生事件反推所有源数据。

移动事件与延时共用字段。转换时为轴标记保留最高两位，将延时限制为不与其碰撞的 0..0x3FFF；这不是实测延时上限或时间单位。长延时可能改变方向标记，因此拒绝，不能静默掩码。普通键和滚轮的已核对 16 位延时范围不变。原厂的零值默认及跨宏 OR 1 规则继续保留，轴标记不因写延时或跨宏拼接丢失。
