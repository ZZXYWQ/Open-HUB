# 迈从原生宏的数据往返

当前启用的 A7 V3 Ultra+ 适配可以读取原生宏、原样保存、导出 JSON，再导入另一个宏槽。未改动名称、模式和事件时，保留整个原始记录，包括未解释的头字段、非延迟记录中的原始字和特殊结束标记。`raw` 是内容来源，不是目标鼠标或宏槽的身份凭证。

符合已核对原厂格式的宏仍可编辑名称、模式、键盘/鼠标/滚动事件及独立延迟。含未知字段的宏暂时只允许原样保存和导入导出，修改会保留草稿并报出具体限制。新建宏不会悄悄清零非延迟记录的非零字，也不会丢弃延迟记录的非零代码。空记录不能借“保存宏”绕过删除时的三组按键引用检查。

保留原厂四个模式值 0、1、3、2。[原厂中文、英文语言对象](development/mchose-mode-state-official-facts.json)明确将模式 2 标为“执行一次”；新建宏默认使用它，已读取或导入的宏继续保留原值。其余模式分别为按住时重复、循环至相同按键再次按下、循环至其他按键按下。没有启用未证实的重复次数字段，也不把非延迟记录中的原始字解释成时间。宏属于同一只鼠标的十八个共享槽，保存后仍由用户把需要的物理按键分配到对应槽。

写入前保存原生完整备份，按 19 字节分块发送，并读取完整宏逐字节核对。保存回执包含已核对的宏内容，界面以它作为下一次编辑和导出的来源，同时保留后来产生的草稿和设备切换隔离。发送失败或回读不匹配会报错，不自动重复发送；真实固件的分块提交不是已证明的原子事务，失败时仍应检查备份和实际内容。

来源为[原厂静态事实及独立向量](development/mchose-v3-macro-official-facts.json)。[数据往返验证](development/2026-10-27-mchose-macro-raw-validation.json)及[模式/身份状态增量](development/2026-10-27-mchose-mode-state-validation.json)覆盖原生测试、界面实际保存/导出请求的生产编解码重放，以及既有界面回归。宏播放仍只有模拟和来源核对，没有向操作系统注入按键，也没有验证实物宏播放。未知事件类型的读取、未解释字段的可编辑语义、完整固件行为及逐型号认证仍未完成。
