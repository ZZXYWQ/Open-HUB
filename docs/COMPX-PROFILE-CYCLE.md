# COMPX 循环板载配置与当前组核对

2026-10-27，已有八款 ATK/VXE/VGN 鼠标的九连接增量。精确型号范围见 [横向滚动](COMPX-HORIZONTAL-SCROLL.md)，不扩展到 Pulsar。

## 原厂事实

固定 SHA256 的 ATK HUB 3.2.27 静态源中，`ConfigFile` 按键类型为 9；`E3.create(t)` 将参数放在第二字节、第三字节置零。实际原厂菜单把“循环配置”绑定为 `E3.create(255)`，所以独立重建记录为 `[9,255,0,77]`。1–4 组直达使用 161–164，与循环值不同；本批没有把它们当成循环，也没有开放直达功能。

原厂 `GetCurrentConfig` 为命令 14，`vf.currentConfigFile` 读取首字节。本项目保存这一原始标记，不凭空转换成界面编号或推断所有固件的有效范围。狙击 DPI 只找到类型枚举名，本次没有足够写入与恢复证据，继续拒绝。

## 接通行为

当前可编辑的非左键可选“循环板载配置”，直接写入一条四字节按键记录，不消耗宏槽、不调用主机输入。硬件读取、离线编辑、保存和 Open HUB 配置导入保留已有 `ProfileCycle` 类型；未知 class9 值、非零保留字段和校验损坏不归一化成循环。

新增按键本身不会立即发送切组命令。驱动首次读取时固定当前组的原始标记，以后每次身份复查都会重新查询；发现标记变化时拒绝旧连接继续读取或写入。EEPROM 写入在读取原行之后、SET 之前再次复查，错误恢复尝试也沿用同一组核对。没有主动选择新组、自动重发或替用户重新应用旧草稿。

当前实现要求实体切组后断开并重新连接鼠标，再读取当前组；界面已说明这一要求。普通扫描会保留原句柄，本批没有伪装成点击刷新即可自动重新打开。

## 验证

新增八项默认测试，覆盖九连接全部允许编辑按键、完整独立黄金报文、其他 EEPROM/另一鼠标保留、重开回读、重复设置零 SET、直达/未知记录不覆盖、Pulsar 和左键门槛、当前组变化拒绝读写、原行 GET 与 SET 之间切组零 SET、缺少标记不假定零，以及原始标记不重编号。测试按函数计八项，部分函数含多个分支。

真实构建 UI 使用原生生成 DTO，九连接分别保留一个已读取循环动作并新增另一个，保存九份完整已知方案。另检查 Pulsar 两连接及 HyperX 没有新增菜单。实际保存的九份方案经过生产配置合并/导入、编译和驱动内存回放，均保持两个循环记录且没有软件输入依赖。

默认原生测试 **841 通过、0 失败、66 忽略**；所需界面方案交叉测试显式执行 **1 通过**。TypeScript/Vite 与非测试原生构建通过。前端 JS 为 **813725 字节**，较上批增加 **190 字节**；没有新增运行时依赖、图片或原厂程序。

## 尚未证明

本批没有实物按下循环键、实际四组切换、断电保存或不同固件标记语义的证据。原始标记相等不证明无线单只鼠标身份，也不证明固件一定在所有切组情形更新该标记。GET/SET 不是原子操作，检查之间切组又切回可能无法检测；模拟零 SET 不能当作实机固件事务证明。

其他板载库的共享宏引用仍未核对，不能因当前组固定就宣称宏分配完整安全。可移植方案仍未绑定持久板载组标记，自动重开与切组后的草稿迁移、直达组动作、原厂完整控制、UI 和灯效验收继续开发。
