# MagDock 灯效快照导出、预览与恢复

开发分支增量，未更新安装或发布版本；完整鼠标验收保持0/100。本页区分新增的实体只读证据、原生模拟事务和实际界面测试。

## 当前实物只读证据

Windows PnP 检测到一个 `3837:1012 MCHOSE MagDock`、usage page FF00 / usage1。零访问权限句柄的 HID 属性/预解析能力查询确认 InputReportByteLength 与 OutputReportByteLength 都是65（含ID），FeatureReportByteLength为0。没有调用操作性 ReadFile/WriteFile 或设置命令；元数据查询不等同于设备完全没有进行底层通信。

随后运行原生 `--magdock-probe` 和新增的显式 `--magdock-readonly-report`，各自只通过 Session 发送GET7。现有65字节 HIDAPI请求成功，读取返回64字节、不带0号report ID，头为 AA 07 02 00 00 1E。解析到流水模式4、模式参数6、红色255/0/0、亮度1、速度1、方向1、同步关闭，固件本地显示0.3。[观察事实](development/magdock-observed-hid-facts.json)与[原始读取向量](../src-tauri/tests/fixtures/magdock-observed-readonly.json)已记录。

这解决了所连接这只底座的描述符长度与GET路径缺口。未改灯效、发送SET39/stream41/reset42、实际音频采集或屏幕取色。64字节是HIDAPI返回形态，不是USB总线抓包；单个设备/固件的读取不能证明所有修订或设置命令兼容，更不能计为完整鼠标或本体RGB认证。以前静态原厂Ff的63字节默认data与本机能力需要分别保留其接口范围，不能据此把native报告改为64。

## 用户流程与文件范围

底座原厂灯效区新增“导出底座灯效”“从备份恢复灯效”。新文件格式 `open-hub-magdock-light/1` 包含固定厂商/产品、读取到的固件显示及全部已知Light字段，不含临时连接号。16KB上限、严格字段/重复键/类型和范围检查，不执行文件内容。早期自动保存的普通Light JSON也可载入，预览明确显示未记录设备及固件；原自动备份位置仍是 `%LOCALAPPDATA%\Open HUB\backups`。

预览按行比较当前/备份的开关、基础模式、同步标记、颜色、亮度、速度、方向和原厂模式参数。新格式固件不一致时阻断，尚不宣称跨固件转换。旧文件没有硬件身份保证，仅在用户明确选定当前MagDock后恢复这些已知字段。软件音乐/屏幕同步方案仍从灯光方案功能单独载入。

导出/预览仅在底座没有本软件正在控制的同步或音乐线程时进行；独立PC同步不受该门槛限制。预览不会停止灯效。应用前重新读取文件并核对SHA-256、预览连接、当前设置和固件；任一变化即拒绝。随后仍在同一连接读取、备份当前设置、再次核对、写入并读回，防止简单的“文件载入就写入”。失败不盲目覆盖恢复。导出文件完整写入并sync_all，恢复前自动备份沿用生产持久化路径。

界面在连接变化时关闭旧预览；离开页面后完成的文件对话框不能发送旧请求或重新打开对话框。恢复成功以同连接读回更新底座草稿。820×560窗口下预览与应用可达。异常结束的效果线程不会因残留JoinHandle永久阻挡备份。

## 验证与保留缺口

新增8项默认原生测试：实际GET响应向量、两项严格文件解析、四项导出/预览/恢复及拒绝条件、异常线程结束后的恢复可用性。恢复模拟核对生产字节、旧快照、写前备份及非灯效字段保留；文件修改或连接变化无设置写入，其他程序改变当前Light时拒绝；活动底座效果不被预览停止。

10项新增真实构建界面检查产生6个请求：1次导出、4次预览、1次明确恢复，再经生产文件/控制器和内存Session回放，唯一设置写入来自明确恢复。原有10项连接与19项独立输出UI检查继续通过，8次连接UI请求的原生效果回放也通过。UI后端为模拟，原生恢复写入亦为内存传输；实体只读验证单独列在上文。
