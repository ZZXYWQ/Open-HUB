# Rival 600：七键与八灯区开发增量

本项目无此型号实物；未发布、未安装，不增加 100 款完整兼容验收数。只开放有线 `1038:1724`；其他接收器、Rival 650、特别配色编号没有据此启用或另行计数。

已接入两档 100–12000 CPI / 100、125/250/500/1000 Hz、七个实体键的完整表和八个独立原生 RGB 区。主左键保留，另外六个键可编辑；第三侧键是实体按钮，原厂默认禁用，已从旧驱动的固定空槽改成真正的可编辑槽。DPI 键是第七键，原生原动作继续可用。支持已核对的标准五键输出、键盘/左右修饰键、六种媒体键、DPI 循环、禁用和逐鼠标软件宏。

按键命令 `31 00` 使用 Feature 报告，不能套用 Rival 310 的 Output 传输。八个灯区为滚轮、Logo、左/右灯带上/中/下，使用独立 `05 00` Feature 报告。每区均有关闭、常亮、呼吸、循环、最多 14 点自定义渐变，保留半百分比位置与独立 16 位周期。新界面按本型号展示六个可编辑键、八区和精确原版外观；不会显示不存在的第八键或第九灯区。

逐物理输入集合和当前控制连接核对与原有有线赛睿共用，两个同型号鼠标的软件宏独立，断线/重新打开后旧恢复记录不得写入新连接。已知完整方案包含六个可编辑键和八区；实际界面保存方案经过文件存储、重载、配置包合并和生产编码回放。全部八区与固定独立参考完整报文逐字节比对，第三侧键与失败缓存另有测试。没有系统输入或实际 HID 写入。

手动板载保存要求当前连接上完整成功应用、全部已知键和所有八区、没有软件宏或待恢复映射；抬升级别也必须包含在完整硬件方案中；发送一次 `00 09 00`。缺区、草稿改变或旧连接拒绝，不确定发送不重发。不自动保存闪存，不宣称回读确认。Windows hidapi 后端按实际 HID report caps 填充短 Feature 缓冲；模型编码测试比较的是有效前缀。

当前状态仍来自模板或本次会话，不能称为完整原厂备份。后续已接入 [GG 私有八区配置与原厂八级抬升](GG-RIVAL600-IMPORT.md)，按原始数据核对 CPI、七键、八区、抬升与宏，非默认原厂内核性能行为完整拦截。任意滚轮与原厂所有特殊输出、原厂宏格式、完整配置读取及完整交互/视觉品质继续开发。这些缺口意味着部分协议实现，不能计为完整兼容。

主要协议事实来自固定 [rivalcfg](https://github.com/flozz/rivalcfg/tree/779ea52c68cbf8d21234d9e0d81718225f680819) 的 `rival600.py` / `test_rival600.py`；八区独立向量见 development/rival600-independent-gradient-vectors.json。独立 [libratbag 数据库](https://github.com/libratbag/libratbag/blob/8235b5bb6032dea15901ab58a8218956f4494d08/data/devices/steelseries-rival-600.device) 确认 1724、七键、八灯区和 CPI 范围。官方[板载保存说明](https://support.steelseries.com/hc/en-us/articles/16551942332301-What-settings-save-onto-my-Rival-600-s-onboard-memory)列出 CPI、回报率、按键、抬升与灯光，但不证明本项目的实现已实物验证。
