# 无序列号有线鼠标的独立软件宏

开发增量；未发布或安装，不增加完整型号验收数。目前只开放已核对的三个有线控制接口：赛睿 Rival 300 `1038:1710`、Rival 310 `1038:1720`、Sensei 310 `1038:1722`。接收器、多鼠标接收器、其他型号与其他品牌没有据此直接开放。

Windows Raw Input 的键盘集合可能不提供可读序列号。现在会读取 Windows 的物理 ContainerId 元数据，核对当前控制接口与键盘集合是否属于同一只设备：型号相符，非空/非零/非全 FF 的容器标识一致，同容器只有一个键盘候选和一个控制实例，已知序列号不能冲突。实际读取使用已有 SetupAPI 帮助函数，不打开额外 HID 控制句柄，也不按路径前缀猜测设备。

每次打开控制接口生成独立连接标记；同路径、同容器重新打开也不会沿用旧关联。应用前、原生写入后启用宏前、停止时恢复前均重查当前集合和连接。其他型号保留唯一序列号核对，并拒绝序列号同时对应多个控制实例的歧义。关联证明只存在内存，不保存为配置所有者，不允许重连自动运行宏。

输入观察器在注册 Raw Input 后记录当前已存在的集合，也处理新集合到达，因此没有收到过 F13 触发事件的集合移除也能停用路由。断开后释放本软件拥有的合成输出，不重新启用；恢复目标无法确认时保留恢复文件。连接变化后的会话也不显示为旧方案仍在运行。观察器不使用全局鼠标/键盘 hook，不屏蔽其他鼠标，也不屏蔽 F13–F24 传递给其他程序。

已连接设备页面只请求该目标核验通过的来源；唯一来源可自动选中。延迟查询使用当前编辑草稿，不能覆盖刚修改的宏；切换鼠标后丢弃旧查询结果。离线编辑页面保持独立，不假装已经连接设备。每只鼠标分别保存完整方案和来源。

赛睿原生命令写整张按键表，重启的新驱动只持有默认模板。新的版本 2 恢复记录因此包含全部已知非主左键的停止后动作和临时触发归属。只接受上述精确型号、完整且不重复的键位集合、已知原生动作和 F13–F24 归属；不允许任意设备/未知动作借此恢复。驱动先在内存验证整表，再用一条原生命令提交；短写不重发、不提交缓存。其他自定义按键不会因逐个恢复宏键而回到默认值。版本 1 既有记录继续按原规则读取。

无序列号的记录重启后不会自动写回。用户在原鼠标页面重新核对当前输入、查看整表并确认后，才允许手动恢复；正在按住触发键时等待释放。此处完整键表是已知模板/会话和用户方案的恢复范围，不能读回或证明其他控制软件对硬件做过的改动。

测试使用真实生产 SteelSeriesDriver、设备管理器、Service、持久化恢复文件、内存传输和记录型输入输出。三组同型号双设备分别检查错误来源零写入、独立触发、只停止一只、保留其他按键、输入移除、相同路径重新打开的零写入、重启不自动恢复和明确手动整表恢复。浏览器读取原生 DTO，检查延迟查询、跨设备切换及独立保存；实际保存的两套方案经生产存储重载和真实驱动回放。本项目没有这些赛睿实物，Windows 消息生命周期以编译和模拟行为覆盖，不能称为实机验证。
