# Attack Shark X11：开发中实验适配

此改动尚未发布或安装。X11 的完整原生方案已经接入设备界面、配置中心、导入、保存和生产驱动模拟；这不等于整款达到原厂功能一致，也不计入 100 款完整验收。X11 的有线与接收器只算一款鼠标。

## 身份与传输

仅 `1D57:FA55`（USB）和 `1D57:FA60`（2.4G）。Windows 只接受 USB `MI_02 / COL04` 控制集合，不回退到任意键盘或鼠标接口。一个设备对象持有一个已打开的 HID 句柄，写入时不重新按 VID/PID 选择另一只设备。蓝牙及 R1 `FA61` 不套用 X11 协议。

使用已有 Windows HID Feature Report，无新运行库、内核驱动、Zadig、WinUSB 或全局按键拦截。扫描和首次读取不发送设置；首次完整状态未知。相邻功能报告至少间隔 250 ms，以免已知固件停止响应。

## 已实现范围

|功能|范围|
|---|---|
|DPI|六档、当前档位、XY 同值；50–10000 步进 50，10100–22000 步进 100；严格查表，不静默取整|
|回报率|125 / 250 / 500 / 1000 Hz|
|控制|左、右、中、前进、后退、顶部 DPI、向上/向下滚轮，八个独立配置；至少保留一个实体左键|
|动作|基础五键、双击、滚轮上下、DPI 循环/增/减、单键及左侧四修饰键组合、已列出的媒体/浏览器/系统动作|
|原生宏|左/右/中/两侧键的五个独立槽；键盘含修饰键、鼠标五键；指定 1–255 次、任意按键停止、按住播放；界面显式录制和编辑|
|宏容量|展开长延时后最多 47 项；超限拒绝，不截断；检查按下/释放配对；尾事件固定 10 ms|
|灯效|关闭、常亮、单色呼吸、霓虹循环、彩色呼吸、DPI 常亮、DPI 呼吸；颜色与五档速度|
|性能|直线修正、波纹修正、4–50 ms 偶数消抖；30–1800 秒休眠、60–3600 秒深度休眠|
|界面与配置|型号结构示意图；完整方案保存、精确品牌导入和摘要核对；逐设备应用；不自动应用导入结果|

宏“任意按键停止”不是触发键开关循环。最后事件的固定延时和固件量化不会被伪装成精确毫秒定时。模板标为可编辑示例，只有用户明确创建或导入后才成为待应用方案。

## 写入与失败语义

状态无法完整读回，不能对未知板载内容做分项读改写。使用严格的 `attack-shark-x11/1` 完整配置格式，由对应驱动验证全部内容后才进行第一条传输；它不是原始 USB 报文透传。其他品牌拒绝此格式。通用软件宏和其他输入来源不能混进此方案。

完整方案同时写 DPI/性能、灯光/电源、回报率和八个控制。按钮映射按原厂顺序一次写全，然后写所绑定按键的宏页，避免每次创建宏时用默认映射覆盖另一个按键。其他未绑定新宏的宏槽不写。

成功仅表示主机完成传输；驱动标记 `write_only_session_cached`，不声称固件接受或硬件校验成功。任一报告失败立即停止、清除已发送配置缓存，报告可能部分生效，不自动重试，也不声称能从无法读取的旧配置恢复。界面保留的编辑方案与硬件状态分开。

DPI 抓包中的字节 14/15 出现 `00 00` 与 `01 01`，公开资料未解释语义。配置保留其配对值，界面编辑不改动；不把它们改名为猜测的功能。其余未解码的 DPI 灯色元数据暂不开放编辑。

## 测试证据

- 固定来源的 320 组 DPI 抓包逐字节比对，有线 52 字节与接收器 56 字节分别验证；保留未知配对字段。
- 53 组独立宏抓包：50 组有效方案逐字节比对，3 组未释放/无对应释放的输入作为拒绝样本；包含页边界、五个宏槽、长延时、鼠标事件和 255 次播放。
- 抓包证明简单延时上限为 1270 ms，1271 ms 才增加扩展事件；修正参考实现写成 1070 ms 的分界，不照搬冲突注释。
- 每一条报告失败、整份方案预验证、短缺字段、错误型号/版本、超容量和非法配置、两句柄隔离、真实 250 ms 传输间隔。
- 浏览器编辑 USB/接收器两份完整方案、七种灯效、八个控制、键盘宏录制、保存后重新导入并交给实际驱动模拟执行；没有 USB 访问。
- 服务层两只同型号分别配置与会话刷新；没有软件输入路由；不明确选择目标时拒绝。

测试源：`src-tauri/src/x11/`、`src-tauri/src/x11_models.rs`、`scripts/test-x11-ui.cjs`；独立输入在 `src-tauri/tests/fixtures/x11/`，只用于测试，不作为应用资源打包。实际 USB 设备测试为零。

## 电量接入开发增量（2026-10-26）

X11 2.4G 的被动输入 `03 55 40 01 XX` 现在接入原生驱动和对应 UI；不发送电量查询命令。协议参考固定在 MIT 社区实现 `49ecf8e6d3bd83bf71e231209d28c5e0e8b71d12` 的 [BatteryMonitor](https://github.com/akawazak/attack-shark-x11-community-driver/blob/49ecf8e6d3bd83bf71e231209d28c5e0e8b71d12/src/main/driver/core/BatteryMonitor.ts) 与 [电量说明](https://github.com/akawazak/attack-shark-x11-community-driver/blob/49ecf8e6d3bd83bf71e231209d28c5e0e8b71d12/docs/battery-status.md)。只解析电量百分比，没有从此报告推断充电标志。

Windows 输入集合必须同时满足精确 VID/PID、USB 接口 2、usage page 0x0A，以及与控制集合相同的非空 `DEVPKEY_Device_ContainerId`。缺失、重复或无法打开时电量显示未知，继续保留原有配置控制；不从同 VID/PID 中任选一条输入路径。使用只读 SetupAPI 属性查询，按 [微软接口说明](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetdeviceinterfacedetailw) 获取所属设备，不拆解路径字符串猜配对。容器对应连接的 USB 设备，并不被称作新的配对鼠标永久序列号。

电量读取为零等待且每次最多 16 条输入报告；0% 是有效值，超过 100%、签名错误或不完整报告均不采信。大于五个百分点的突变需要相同值重复确认；90 秒没有有效报告后恢复为未知，断开/读取失败会清掉旧值。有线和离线配置明确显示对应状态。界面每两秒单独读取电量，隐藏后停止，保留未保存的完整设备方案。
