## 原生读写与配置

ATK HUB 3.2.27 公开静态代码的 `pb`、`rd`、`_getMouseDpiColors`、`setMouseDpiColors` 表明：八档颜色占用地址 44–75，各四字节，顺序 RGB 与校验字节，四字节模 256 求和为 0x55。原厂分四次读取/设置相邻两档。Open HUB 沿用已有 EEPROM 单行传输，逐档读取、校验并只写所选四字节记录；独立重建的报文不称为 USB 抓包或实际固件验证。

核心 DTO 新增可选的 `dpi_color_stages`、`dpi_colors` 和设置 `DpiColor`。未启用型号的空字段不序列化，旧文件缺字段仍可读取。颜色表按逻辑档位表示，未伪装成八个物理 LED 灯区。

硬件读取导入和“保存完整方案”保留所有实际校验通过的颜色，包括当前未启用的 DPI 档位。配置中心编辑、Open HUB 配置包导入/导出及会话刷新保留精确档位与品牌/型号。此处读取的是已连接鼠标的配置；未新增 ATK/VXE/VGN 私有厂商文件解析器。

界面提供八个独立颜色输入，标出活动档位和未启用档位。原生灯效的“当前 DPI 档位指示灯”常亮颜色与色表保持一致：切档显示该档颜色，修改当前颜色同步到该档记录。原生关闭状态不因修改色表而开启；未知灯效不自动替换成关闭或常亮。

写入顺序为 DPI 等设置、逐档颜色、当前档灯效。保存文件中若同时声明相冲突的当前档颜色和色表，原生校验拒绝；重复档位、越界或不支持型号同样拒绝。服务在任何设置或宏分配之前，确认每个所选档位有本次可校验的原始颜色。单独驱动写入再次检查原始行校验，并沿用身份核对、写后回读及原行恢复尝试。短写返回不确定错误，不自动重发；恢复尝试不能证明硬件原子事务。
