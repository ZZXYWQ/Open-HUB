# A7 实时 USB / 无线独立回报率

开发分支增量，完整型号验收仍为 0/100；发布和安装版本保持 0.3.7。本次没有物理 HID 访问或设置写入，没有新增依赖和图片。

## 实现

完整 M HUB 方案此前已能分别保存 USB 和无线回报率，但实时面板只有同步修改两者的按钮。现将它拆成两个有当前选中状态的按钮组，各有 125/500/1000/2000/4000/8000 Hz。操作只变更对应连接，不清除已有 DPI、性能或名称草稿。

新 `connection_rate` 请求包含当前设备/连接、板载组、连接种类和实际读取的完整 19 字节设置前像。原厂 `tgt` 编码器与 `o1e` 解码器证明 USB 在 byte1 高半字节、无线在 byte2 高半字节；低半字节是 DPI 索引，不能当成另一种回报率。正的原厂界面索引编码时加一，因此不开放未证明的 250 Hz。

后端先校验值与完整前像，再完整读取并同步落盘备份；备份后复查板载组和全部设置。只修改选中高半字节，保留另一连接、两个 DPI 索引和其余所有原始字段。发送一次 SET，随后有限读取核对；不会因为未核对成功而重复 SET。备份后外部变化在 SET 前拒绝；忽略写入等读回失败显示可能部分生效和原始备份路径。设置已经相同时，没有 SET 或新备份。

旧的通用回报率接口仍保留同时设置两种连接的语义和已有读回校验，改为共用完整备份、备份后复查与错误上下文。移除无人调用的旧 raw-v1 自动备份写入器，避免继续生成不能由完整恢复界面直接使用的简化备份；没有删除用户已有备份。

## 验证

五项新增默认原生测试覆盖双连接和双鼠标隔离、DPI/其余字段/宏与原始备份保留、无变化不写入、无效与过期前像拒绝、备份期间变化和只确认命令但不改变设置的错误回读，以及通用接口的完整备份和读回。已有非空宏记录及其他板载组映射在独立回报率测试中保持不变，原始完整备份包含同一份宏正文。

构建的实时面板产生四次实际请求，经原生所有者校验和生产设置事务回放。界面九项检查同时覆盖选中状态、另一连接保留、DPI 草稿保留和第二只鼠标独立。原有十一组草稿界面检查、二十二项异步生命周期检查及两次重连原生回放通过。旧回归预期已更新为完整 v3 备份和无变化不发送；没有为维持旧测试而重新引入重复 SET。

默认原生测试 739 项通过、0 失败、59 项忽略；新界面回放及既有重连回放已显式执行。TypeScript、Vite 与非测试开发构建通过。前端 JS 为 795982 字节，相比上一增量增加 397 字节。没有据此宣称物理 Hz 时序、断电保存或全部原厂功能已验收。[验证记录](development/2026-10-27-mchose-independent-rates-validation.json)。

回报率 SET 已经读回匹配后，如果刷新完整状态才出现 FF 或其他错误，返回“设置已读回匹配，但完整状态刷新未完成”和原始备份路径，不误报没有写入。传输层 FF 错误只描述身份未知，不再自行断言事务是否写入过设置。新增故障注入验证了这条路径只发送一次 SET、保留已生效的回报率及备份。

## 型号差异与编号澄清

同轮静态核对得到 [17 个型号的部分功能门槛](MCHOSE-MODEL-GATES.md)。这批源码事实服务于逐型号实现，未注册任何新的硬件编号或兼容入口。

之前将原厂表的 USB productKey 中 4033 与 GET0900 历史载荷中的 4026 直接称为型号编号冲突，证据不足。两者分别来自设备描述信息和协议载荷，尚未证明需要相等。当前仍仅启用原先精确命名的接收器和已观察身份字段；不将编号来源的澄清当成开放 4033 的依据。身份 FF、RF 单只鼠标身份和型号实机验收仍继续处理。
