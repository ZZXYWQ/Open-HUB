# SC620 性能/电源字段与 22 键设置转换

2026-10-27。延续 [原厂设置表工作](SC620-OEM-SETTINGS.md)，未开放设备驱动或 UI，不增加完整型号。

## 原厂语义和编码

同 SHA 的官方安装包仅静态提取原程序和两份语言资源。核对原始机器码、控件标签、键名、参数读写以及导入表：

|设置|原厂来源|载荷字段|已核对取值|
|---|---|---:|---|
|LOD|liftoff_height|41|低 1 mm / 高 2 mm，对应 1/2|
|滚动反向|scroll_flag|40|正向 0 / 反向 1|
|电竞模式|e-sports_flag|45|关 1 / 开 2|
|休眠时间|sleep_light|44|1、3、5、10、20、30、60 分钟|
|波纹控制|sensor_flag 的 0x04|42 的 0x10|独立开/关|
|直线修正|sensor_flag 的 0x08|42 的 0x01|独立开/关|
|Motion Sync|sensor_flag 的 0x10|42 的 0x20|独立开/关|

这些是原厂控件与编码的静态证据，不等于已验证 SC620 实际固件对每个字段的支持和效果。

休眠控件调用 `MComboBox.GetCurData`，不是选项序号。七个 AddItem 的数据值是 1/3/5/10/20/30/60；最后一项的标签是 1 小时，数据值 60。没有把全局语言表中的“不休眠”标签套到这个菜单，也没有把值 0 伪装成不休眠。

原厂 sensor_flag 的低两位未进入此 SC620 原生写入路径，仍在来源字段中原样保留；仅 0x04/0x08/0x10 参与上述映射。其他未核对的更高源位不会被忽略，而是保留为未转换字段并阻断整份源准备。

## 原始状态保护

原生镜像提供这些字段的独立读取和修改。LOD、休眠、滚动方向、电竞模式遇到未知原始值时返回未识别，不替换为默认；其他编辑不改变未知值。三项传感器功能仅修改各自已核对的位，保留同一字节的其余位和未选中的功能。修改参数不触碰 DPI、颜色、灯效、按键或宏库。

原厂设置表转换现可表达全部 22 个已核对键的受限取值，新增六个来源键为可选，以保持旧 16 键预览格式。文件侧 profile ID 继续不解释为硬件页或鼠标身份。其他字段、超出已核对取值的值或未知源位仍保留并阻断整份准备。

`dpi_flag` 存在明确边界：原厂初始化默认字符串为 5，读取函数把硬件阶段字段直接存入它，写入函数却始终写固定 6。这次只把与当前原生镜像六档布局一致的来源值 6 视作已转换；包括 5 在内的其他值保留为未转换，不能静默升级成六档。这也意味着并非所有原厂初始文件都已可完整转换。

## 验证

新增 **10 项默认测试**。448 组 LOD/休眠/方向/电竞/传感器组合核对独立字段及原像保留；全部 256 种原始传感器字节逐一检查各个开关不会清掉其他位。另核对未知原值、非法参数拒绝、32 种来源传感器位/元数据组合、旧 JSON、取值语义、预览重算和 DPI 档数门槛。

独立 JSON 样本给出 22 个源字段和完整 65 字节黄金报告。测试在临时 SQLite 样本中写入这些字段，再由生产只读解析器、源转换和原生镜像编译核对；保留未知原生传感器位 0x84，读取后源数据库逐字节不变。样本为合成数据，不是原厂导出或实机抓包。

SC620 模块 **81 项通过**，主程序 **918 通过、0 失败、68 忽略**，非测试构建通过。本批没有运行依赖、前端图片或其他界面资源；原厂安装包、程序及两个语言资源共四份临时载荷已清理，残留原厂载荷为零，没有执行厂商程序。
