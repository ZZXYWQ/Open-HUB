# 罗技板载宏：独立修饰键保持

现有单次板载宏增加左右 Ctrl／Shift／Alt／Windows 的独立按下和松开。宏仍在选定鼠标的板载格式1中编译和保存，不改为主机输入，不新增设备准入或完整型号计数。

## 编码依据与行为

已固定的公开 `cvuchener/hidpp` 提交 `474ac10db5673da8f2f1c8911414d394c0eb6d12` 中，MacroFormat 将独立 ModifiersPress／Release 转为 `43/44 + modifier mask + 00`；普通按键使用零修饰操作数和真实 HID 键码。新增审计核对保留文件的 Git blob `3fd8b663e43e9ebe61c89b8e5330303c4440d958` 与固定树记录一致，独立实现该格式，未复制参考运行库。

E0..E7 映射到 bit0..bit7，各个事件只携带本次按下／松开的修饰位，不把它变成累计状态快照。例如 Ctrl 按下、A 按下、等待17ms、A松开、Ctrl松开，完整编译为：

`43 01 00 43 00 04 40 00 11 44 00 04 44 01 00 FF`

八个独立侧别都核对了字面向量，多修饰键同时按住时保持原始顺序。宏仍要求所有键／鼠标按下与松开成对。快捷键点按若包含已经单独按住的同一修饰位，其释放可能破坏前面的保持；此情况在任何 FeatureRequest 前整体拒绝。其他不重叠的点按仍允许，用户也可用分开的按下／松开表达组合。

界面在“键盘按下／松开”中提供八个侧别；“快捷键点按”的主键仍不提供E0..E7，其八位修饰勾选保持原作用。编辑后必须重新检查，仍只有单次播放；循环／文本／未核对的滚动移动写入没有因此开放。

## 写入范围与保护

保持既有直接USB、可靠unit-id和当前连接、报告内存格式／扇区几何、具体槽／层／物理记录门槛。修饰键保持可跨255／256字节页的显式五字节JUMP，编译器不会为了分页插入释放。共享引用扫描、空闲页保护、至少一个普通层左键、写前备份、宏页后绑定、逐阶段全库读回、有条件恢复及旧连接拒绝继续使用既有路径。

不触碰其他品牌编码器或全局输入规则，不把兼容格式当作所有罗技型号已完成，也不扩大接收器写入范围。
