# COMPX lighting row reconciliation

2026-10-29 development change. Existing supported models only; no model or completed-compatibility count increase.

Palette color edits, the native eight-byte DPI indicator record, and legacy Off/Static lighting now use one conditional transaction implementation. Every operation captures the ten-byte system row (including active DPI selection), the complete 32-byte palette and the eight-byte indicator row. Model identity and current bank are checked around captures and each write. A static effect writes its active palette color before enabling the mode; an error after either write reconciles both affected records instead of leaving half the requested setting applied.

The transaction compares complete current state before and after writes, preserves inactive colors, unknown unselected bytes, speed and brightness, and skips unchanged writes. A malformed active color checksum is retained rather than overwritten. Detailed indicator editing still requires a recognized original indicator state. Existing per-model capability validation remains unchanged, including models with no controllable light and exact eight-color palette scope.

Recovery freshly reads all guarded state. Each attempted row must match either its original or requested complete bytes, and every unattempted byte plus system selector must remain unchanged. Only then may original rows be restored, in reverse order, with verification after each. A short write whose full effect can subsequently be verified may be restored; a foreign/partial row, changed selector or failed recovery is reported uncertain and is not automatically retried. No recovery writes the desired effect again. This replaces the previous single-row blind restoration for these lighting paths. Generic DPI/basic button/Pulsar shortcut writes still have separate preexisting recovery paths; this change does not establish complete device transaction safety.

Validation: six new production-report memory-transport tests span every currently registered legacy-light model and every detailed palette/indicator model. Coverage includes exact successful byte changes, unchanged no-op, independent second device, failure before/after each of two SETs, one-row color/indicator failures, foreign active/inactive palette and mode/selector changes, invalid active color, and failed recovery. Existing short-write tests now assert the restoration report and complete original memory image after state reconciliation, rather than requiring no recovery attempt. One injected selector change initially equaled the fixture's active slot; the test now computes a different valid slot and asserts its fault really changes state.

Results: 1058 default main-program tests passed, zero failed, 92 ignored pending separate artifacts. Headless Edge saved ten OEM light/performance profiles through the current React UI; explicit production compiler/driver replay passed. UI IPC, inventory and dialogs are mocked; transport is memory-backed. Native development build passed (six preexisting warnings). No physical lighting/playback/timing equivalence, atomicity, race exclusion or full-model acceptance is claimed.

No dependencies, assets, version, installer or releases changed. [Current model count](MODEL-COUNT.md): 42 partially integrated, 0/100 fully accepted. Protocol layout and source scope remain those documented in the existing COMPX palette/indicator work and pinned ATK HUB 3.2.27 evidence.
