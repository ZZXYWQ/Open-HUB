开发分支增量，未发布或安装；完整型号仍为 0/100。

完整 M HUB Plan 之前已捕获调用方连接，但旧板载引用和通用 DPI 配置还可能重新解析到同一路径的新连接。本次原生 dispatcher 在任何 I/O 前统一调用 `mchose_target::check_profile_connection`，依据实际设备厂商决定门槛，不再依据 profile 是否包含完整 Plan。完整方案、旧板载引用及未指定品牌的 Desktop 都受约束。配置中心和顶部菜单发送选中设备的连接；托盘把菜单生成时的连接封入操作，点击时不取得新标记。缺少连接的迈从项目禁用；后端仍拒绝省略或过期标记。

模拟保持同一路径、同一 observed owner，只改变连接 generation，证明重新解析 owner 不能代替调用方捕获。三个配置形态的四种无效上下文均拒绝，原 store 保持、无通信或备份。托盘操作本身通过实际生产函数生成并解码；未启动系统托盘 UI。新一轮测试不证明无线接收器不断开时换配鼠标的身份。

构建的 React 界面生成旧板载与通用 DPI 的 10 次实际请求，8 次当前连接、2 次重连竞争；生产预检和逐设备副本存储回放通过。这个新回放只覆盖预检/存储，不宣称执行了这两类配置的硬件命令。既有完整方案的 5 次界面请求继续走生产差异事务，罗技和逐鼠标归属的界面/原生回放继续通过，罗技不要求额外迈从连接参数。

默认原生测试 688 项通过，53 项默认忽略；三项指定输入的回放分别手动运行通过。TypeScript、Vite 和非测试开发构建通过。没有新增依赖或图片，没有物理 HID 访问、原厂代码执行、全局输入注入或安装包操作。
