# COMPX 已绑定宏正文导入与逐键播放确认

原厂文件中class6的第三字段可能来自鼠标回读，也可能来自原厂UI编辑；同一数值1可表示原生单次，也可表示UI的再次按下停止。因此不自动猜播放方式。导入已解析按键时，遇到可完整转换的已绑定宏，先显示每个实体按键的宏名、原厂槽、文件编码及全部转换事件，用户逐键选择单次/按住循环/再次按下停止/固定2–252次，再预览和保存。

## 正文与范围

[固定原厂来源与编码差异](development/2026-10-28-compx-file-macro-source.json)。读取同一文件的deviceConfig.macroList，按绑定槽索引找正文，保留名称、键盘/左右修饰键/五种鼠标输出的事件顺序和逐事件延时。七种已核实媒体用途仅接受可准确表示的相邻按下/抬起和延时；保持40ms等不可表达形式拒绝，不缩成点按。原厂滚轮方向/中性记录及电源、移动等未完成转换，不丢弃事件或创建空宏。

以本次固定3.2.27原厂写入函数为依据，零事件延时实际写成1ms，转换器按相同规则处理并在预览说明。负数、浮点、超过65535ms、超过70事件、空正文、缺少名称和未平衡输入拒绝。名称保存在Open HUB配置中心，不声称鼠标固件保存原厂名称。同一库槽被两个按键以不同方式绑定时，分别保留独立的按键宏方案及明确选择的模式。

只转换本次绑定引用的正文；未绑定库条目仍不在范围。若原厂导出已丢失事件类型，无法从不存在的JSON内容猜回。固定来源的getMacro存在非滚轮事件被标成Normal_Key的路径；界面提供完整事件核对，不将JSON转换当成原始硬件无损捕获。

## 检查与时间窗口

只读检查先验证精确目标、DPI/回报率、完整物理按键表及正文可转换性，不返回可保存的默认单次方案。逐键模式初始均为空；未确认任何一项时禁止生成和保存。检查返回整个文件SHA-256，确认后再次读取时比对，文件变化直接拒绝并要求重新选择，防止旧确认套在新正文上。更改来源/目标/选择范围或取消文件对话框会清除旧预览和确认。

保存后使用既有生产配置校验、设备选择和原生宏事务，导入本身不访问鼠标或注入按键。型号范围未扩大，其他品牌宏格式没有套用。尚不具备任意原厂文件完整迁移或真实播放等价结论。
